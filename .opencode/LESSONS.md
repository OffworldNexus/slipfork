# Lessons Learned (`.opencode/LESSONS.md`)

Verified host, kernel, Btrfs, namespace, `crun`, and VM facts. Append 1–2 lines whenever you discover a non-obvious trap.

- **`/tmp` is RAM-backed `tmpfs` with no reflink clone ioctl:** Never put worktrees, CoW snapshots, `PGDATA`, or Cargo scratch under `/tmp` — it consumes RAM and returns `EOPNOTSUPP` (`95`) on the reflink clone ioctl (`0x40049409`). Keep worktrees under `.worktrees/` and CoW state under `~/.cache/slipfork`, `.slipfork/`, or `/var/tmp`.
- **Identity-mapped user namespaces do NOT keep `CAP_NET_ADMIN` on their own:** Write `deny` to `/proc/self/setgroups`, then `"$UID $UID 1"` to `uid_map` and `"$GID $GID 1"` to `gid_map` to keep `geteuid() == $UID` (so `postgres`/`initdb` run), but the subsequent `setresuid` clears the capability sets, so `ip link set lo up` fails `EPERM`. `unshare --user --map-current-user --keep-caps` keeps `CapEff=000001ffffffffff` while `id` still reports `uid=1000` (verified live); `--keep-caps` is mandatory for loopback and pods.
- **Ubuntu's `kernel.apparmor_restrict_unprivileged_userns=1` blocks unprivileged user namespaces entirely:** Persist `kernel.apparmor_restrict_unprivileged_userns=0` in `/etc/sysctl.d/99-slipfork-userns.conf` (and `sysctl -w`) or grant a profile; `tools/do_vm.py` provisioning does this and verifies `unshare --user --map-current-user --keep-caps --net -- true` for the suite account.
- **Multithreaded `setns` into an unprivileged world `netns` fails:** `setns(CLONE_NEWNET)` needs `CAP_SYS_ADMIN` in both the caller's and the target's user namespace, and `setns(CLONE_NEWUSER)` returns `EINVAL` in a multithreaded process. Enter worlds through a persistent PID 1 `slipfork-world-init` and pathname `AF_UNIX` sockets instead.
- **Unprivileged `:80` inside a world netns has two independent mechanisms:** Either keep `CAP_NET_BIND_SERVICE` in the user namespace (`unshare --keep-caps`) or set the per-netns sysctl `/proc/sys/net/ipv4/ip_unprivileged_port_start=0`. Both bind `127.0.0.1:80` with zero host privileges.
- **`CLONE_NEWIPC` is required for parallel PostgreSQL worlds:** A separate `netns` does not isolate System V shared memory, so two worlds collide on `shmget` key `90000`. Include `ipc` in the world namespace set.
- **Git refuses D/F refname collisions (`refs/heads/<fork>` vs `refs/heads/<fork>/wip`):** Both `files` and `reftable` backends forbid a ref and a directory of the same name. Keep branches at `refs/heads/<fork>` and store synthesized dirty snapshots under `refs/slipfork/<fork>/wip`.
- **`crun` as a non-root user needs an explicit, minimal `config.json`:** With `geteuid() == $UID != 0`, pass `--cgroup-manager=disabled`, declare `user` + `pid` + `mount` + `ipc` + `uts` (omit `network` to share `127.0.0.1`), and use identity `uidMappings`/`gidMappings`. Omitting `user` triggers `newuidmap` (`EPERM`) or `setresuid(0)` (`EINVAL`); omitting `pid` blocks a fresh `/proc` (`EPERM`); omitting `$UID` from the read-only `/etc/passwd` bind makes `postgres:18` `initdb` exit `1` (`could not look up effective user ID`).
- **`buildx --output type=local` extracts files owned by the invoking `$UID:$GID`, never `root:root`:** Inside `unshare --mount`, `mount -t overlay overlay -o userxattr,lowerdir=<world_mp>:<app_rootfs> <merged>` with two lowerdirs and no upper/work dir mounts natively read-only on XFS (`EROFS`). `mount -o remount,ro` on an upperdir overlay fails with `fsconfig: No changes allowed in reconfigure`.
- **`pivot_root` requires `chdir` into the new root first:** `cd <merged> && pivot_root . .old_root && umount -l /.old_root`. A relative `.old_root` after a stale cwd unmounts the wrong tree.
- **`pgrep -x` counts zombies, so poll-based teardown measurements lie:** `pkill` + `pgrep` can report a process alive long after `SIGTERM` because the parent never `wait()`ed. Measure teardown with `Popen.wait()` / `waitpid`, not process-table polls.
- **`pkill -f "<pattern>"` over SSH can kill your own remote shell:** Its command line contains the pattern, so the session exits `255`. Use `pkill -x <comm>`. Also remember `cp --reflink=always` needs both paths on one filesystem (`Invalid cross-device link` from an overlay `/root` to XFS `/mnt`).
- **A read-only Btrfs subvolume must have `BTRFS_SUBVOL_RDONLY` cleared before deletion:** `BTRFS_IOC_SNAP_DESTROY_V2` rejects a subvolume that still carries the flag, so destroy is `BTRFS_IOC_SUBVOL_GETFLAGS` → `BTRFS_IOC_SUBVOL_SETFLAGS` with `flags & !BTRFS_SUBVOL_RDONLY` → destroy. Unprivileged deletion additionally needs a filesystem mounted `-o user_subvol_rm_allowed`, or it fails `EPERM`.
- **A real Btrfs snapshot is sealed with `BTRFS_SUBVOL_RDONLY` (`ro=true`), not a `0o555` mode:** On the real kernel assert that a new entry write fails and that removing sealed payload fails; never assert on the mode bit.
- **Child PID-namespace PID 1 has asymmetric signal rules:** Per `pid_namespaces(7)`, `SIGKILL`/`SIGSTOP` from an ancestor namespace are forcibly delivered to a child namespace's PID 1, while an unhandled `SIGTERM` is dropped (`SIGNAL_UNKILLABLE`). `slipfork-world-init` must read an `O_CLOEXEC` stdin lifeline until EOF and exit `0`; `prctl(PR_SET_PDEATHSIG)` fires on creating-*thread* exit and breaks thread-per-RPC daemons.
- **Reap the `unshare` launcher before polling `/proc/<init_pid>`:** `unshare`'s `waitpid` reap and mount-namespace teardown remove `/proc/<init_pid>`, so polling early burns the `SIGKILL` budget under load. Run `unshare` with `--kill-child=SIGKILL` and verify `/proc/<pid>/ns/pid` identity before trusting a PID.
- **`AF_UNIX` `sun_path` is 107 bytes:** `<state>/ctl/<world>/netns.sock` overflows under a deep `$HOME`. Honor a short scratch root (for example `/var/lib/slipfork/t`) in every suite and in the VM harness.
- **LLVM coverage profiles need a writable path and a graceful exit:** `-C instrument-coverage` flushes only when the process exits cleanly (LLVM's `atexit` writer), so a `SIGTERM` handler must `exit(0)`. Build scripts should set `LLVM_PROFILE_FILE=/dev/null`, and a `ProtectSystem=strict` unit needs the profile under `~/.cache/slipfork` — a `/var/lib/...` path is silently unwritable.
- **The ingress forwards only the bytes it already read before reading the backend response head:** A backend must answer head-first or a larger-than-buffer upload deadlocks. An upgraded WebSocket also holds an ingress relay slot until the client closes it.
- **The zero-setup daemon lives in its own process group:** Reap it by the PID that `DaemonControlClient::bind(&runtime_dir).status()` reports, never by the CLI's pgid. Browser availability comes from `DISPLAY`/`WAYLAND_DISPLAY`, so a headless `env -i` harness must set `DISPLAY=:0` for the real opener fixture.
- **A backing-service OCI `config.json` must never carry the world component env:** Compose the bundle from the inherited allowlist plus the service's own `spec.env`. `restart_with_env` refuses a container, so component secrets never land on disk.
- **Child-PID-namespace `namespaces.json` must translate `/proc/1/ns/*`:** Inside `--pid --mount-proc`, `slipfork-world-init` only sees `/proc/1/ns/*`, which on the host resolves to `systemd`. Store `/proc/<init_pid>/ns/*` instead. Unprivileged host `nsenter --ipc=…` also needs `--user=/proc/<init_pid>/ns/user --preserve-credentials`, because `ipcns_install` checks `CAP_SYS_ADMIN` in both `current_user_ns()` and `ipc_ns->user_ns`.
- **`crun` one-shots and `exec` have two sharp edges:** Reap an already-exited one-shot container (`initdb`) with `try_wait` before `crun kill`, because `crun run` unlinks `<id>/status` on exit. And `crun exec` ignores the host `Command::env`, so pass `PS1`/`PROMPT` through `env` inside the executed argv.
- **World-booting suites need a Btrfs host:** Static checks stay green and fast on a non-Btrfs XFS host, so live suites run through the dedicated VM target and fail closed (never skip silently) when the filesystem is not Btrfs.
- **Hermetic `git` probes need a fixed locale and an explicit topology:** Pass `LC_ALL=C` and `LANGUAGE=C` so gettext never translates diagnostics; probe `--is-bare-repository` before `--show-toplevel`, because a bare repo has no worktree (`exit 128`, "this operation must be run in a work tree"). Only `fatal: not a git repository (or any ` means non-repo — broken `.git` pointers, `safe.directory`, and corrupt `.git/config` also exit `128` and must surface `stderr`. Never derive a canonical slug from the `--git-common-dir` basename: submodules resolve to `.git/modules/<id>` and `--separate-git-dir` resolves to the external store.
- **Never let a production composition root wire a fail-closed placeholder:** An `Unavailable*`, `Unimplemented*`, `Todo*`, `Stub*`, or `Fake*` adapter, or a `todo!()`/`unimplemented!()` body, turns a parsed command into vaporware. Ship the real adapter or delete the command.
