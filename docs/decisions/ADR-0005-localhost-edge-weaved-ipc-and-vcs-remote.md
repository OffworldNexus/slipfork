# ADR-0005: Single-Origin World Invariant (`WorldOrigin`), Port-80 `*.localhost` Edge (`slipforkd`), Tunnel Weaver Leases (`weaved`), and `VcsWorkspace`

- **Status:** **Superseded for `0.1.0` by `ADR-0011`** — `0.1.0` ships exactly one origin kind (`struct WorldOrigin { url }`, the `.localhost` ingress) and no sharing surface: no `share` subcommand, no `DaemonControl` share/unshare seam, no `TunnelRegistrar`, no `shared_hosts` table, no `308`/`421` shared-world rules. Everything below about a second origin, tunnel leases, and redirects is **future `0.2.0+` intent, not a shipped capability**; read those sentences as "will". Original status: Accepted — amended for M2 & M3 (`M3.25` world-identity & `--world` selector reconciliation; normative specification for single-origin worlds, unified unprivileged `slipforkd` daemon authority & `LISTEN_FDS` activation, port-aware `WorldOrigin::local(&route, ingress_port)` + in-netns loopback bridge, `snow.yml` `ingresses` prefix routing, `<= 31`-byte Tunnel Weaver service labels, the future tunnel lease lifecycle, `world_id` / `--world` selector rules, and `VcsWorkspace`; `H-005`, `H-008`, & `H-010` validated, `H-006` closed by deferral)
- **Date:** 2026-11-15

## Context

1. **Dual local + tunnel URLs corrupt stateful web apps:** Exposing both `http://<fork>.<project>.localhost` and a public tunnel URL simultaneously splits `BASE_URL`, `CSRF_TRUSTED_ORIGINS`, cookie domains, OAuth callbacks, S3 presigned URLs, and absolute links in outbound emails — and baking any origin into a reusable fixture snapshot leaks stale URLs into subsequent forks and test slots.
2. **Offline-proof loopback routing & loop-free ingress:** RFC 6761 reserves `*.localhost` for loopback (`127.0.0.1` / `::1`) natively in Linux and browser Secure Contexts without external DNS or custom CAs, while a future optional public origin via **Tunnel Weaver (`weaved`)** will have to route into isolated world network namespaces through `slipforkd` without redirect loops, external crate linking, or orphaned leases.
3. **Zero-`cd` agent workspaces (`git` + `jj`):** Developers need `slipfork shell [--world <world>]` plus `git pull slipfork <fork>` and `git fetch slipfork '+refs/slipfork/<fork>/wip:refs/slipfork/<fork>/wip'` across both Git worktrees and Jujutsu (`jj`) workspaces without mutating live working trees or colliding with Git's `refs/heads/<fork>` D/F refname rules.

## Decision

> This ADR is the single normative home for the single-origin invariant, `slipforkd` shared ingress (`H-008`), OSPP precedence, and `.localhost` routing (§1), plus canonical VCS `ProjectSlug` discovery + `VcsWorkspace` (§3). The tunnel-lease lifecycle and the shared-world edge rules (§1 `Shared` paragraphs, §2) are **future `0.2.0+` intent**: `0.1.0` implements only the single `Local` origin (`ADR-0011`). `ARCHITECTURE.md` keeps only concise Rust port signatures, and `docs/design/target-dx.md` keeps only user-facing CLI examples.

1. **Single Canonical Origin Invariant (`WorldOrigin`), OSPP Precedence, and `slipforkd` Edge Ingress (`H-008`):**
   - **Single-Origin Invariant & Port-Aware Local Constructor (`H-008`, `H-010` #2, normative):** A world has **at most one public origin** — **never both, never two**, ratifying the owner's release-gate directive: *"a given environment is going to be either shared either not shared but will have at most one URL (and if you hit the local URL of a shared one you're just sent to the shared URL)"* (`H-008`). In `0.1.0` that origin is always the `.localhost` one: `struct WorldOrigin { url }` (`crates/slipfork-world`) has exactly one constructor and no `kind` tag (`ADR-0011`). A future release may add a second, tunnel-minted origin kind beside it (a `Shared` variant of `WorldOrigin`), still with at most one reachable URL per world. World cards and `slipfork list` MUST print **exactly one URL per world** (`origin.url()`), and `StaticUrl`/S3 signing, email absolute links, and OAuth callbacks all derive from that single origin. `WorldOrigin::local(route: &LocalHostRoute, ingress_port: u16)` (`route.snow_domain()` MUST be `None`) is the **sole constructor** of a `Local` origin: it renders `http://<host>` when `ingress_port == 80` and `http://<host>:<ingress_port>` otherwise (e.g. under unprivileged `slipforkd --listen 127.0.0.1:0`, `H-010` #2). Each world also runs a lightweight **in-netns loopback TCP bridge** on `127.0.0.1:<ingress_port>` piping into `slipforkd`'s HTTP ingress so `$BASE_URL` resolves identically from host browsers and from processes inside the world's `netns`. Additional `snow.yml` `domains[].id` hostnames (`<domain>.(<fork>.)?<project>.localhost[:<port>]`) remain valid local ingresses routed by `slipforkd`, while only `origin.url()` is printed and fed into `BASE_URL` / cookies / CSRF.
   - **Boot-Time Origin Assignment & Per-World DAG Split (normative):** `WorldOrigin` is known before and assigned at **world materialization**, never sealed into a reusable snapshot. `${{ resources::app.url }}`, `${{ domains::<id> }}`, `BASE_URL`, `CSRF_TRUSTED_ORIGINS`, cookie domain, OAuth redirect URIs, email absolute links, `AWS_S3_CUSTOM_DOMAIN`, and any `django.contrib.sites` / Wagtail `Site.root_url` row are **per-world values resolved at boot** and MUST NOT be baked into an origin-independent (`per_world = false`) `[fixtures.<id>]` snapshot (`ADR-0003` §1); fixtures that persist absolute URLs MUST set `per_world = true` so they never share across worlds and run only after `WorldOrigin` assignment. Per the "no stringly plumbing" law (`ADR-0006` §1), `modes.local` MUST NOT carry a hardcoded `BASE_URL`-style literal — Slipfork supplies the resolved origin at boot.
   - **Origin Is Not an OSPP Value & Precedence Rule (normative):**
     - `WorldOrigin` is **NOT** an OSPP (`ADR-0001`, `ADR-0008`) value: OSPP supplies `vars`, `secrets`, remote S3 coordinates, and seed dumps from a remote control plane, whereas `WorldOrigin` is a property of the live *world instance*, known only to Slipfork at materialization time.
     - The Slipfork-assigned origin **always wins** over any provider-supplied `domains::` value; a provider bundle MUST NEVER introduce a second reachable origin. `${{ domains::<id> }}` resolves strictly to `<id>.(<fork>.)?<project>.localhost` derived from `(ProjectSlug, WorldTarget, id)` via `LocalHostRoute`. If a future release introduces a tunnel-minted origin kind, referencing `${{ domains::<id> }}` in such a world will fail closed because only one public origin exists per world. `domains` remains in the `OSPP v1` wire schema strictly for `cloud` deployments.
     - **M2 Dependency Rule (normative):** **OSPP is not a prerequisite for M2 (or M3).** M2 starts and runs end-to-end with `FileVaultProvider` (`0600` local vault) alone and derived `.localhost` origins; `OsppClient` / `OsppSecretProvider` (`ADR-0008`) is an optional accelerator for team/cloud parity, never blocking `slipforkd`, `up`, or `shell`.
   - **Unprivileged Unified Daemon (`slipforkd`), Explicit `LISTEN_FDS` Role Order & `ingresses` Prefix Dispatch (`H-008`, `H-010` #1, `ADR-0008` §5):**
     - `slipforkd` runs **unprivileged as `User=<developer-user>`** (`H-010`'s `%i` shorthand denotes the developer's own OS account, resolved once at the CLI composition boundary via `UserIdentity` / `getpwuid_r(geteuid())` into non-template `slipforkd.{socket,service}`) with empty `CapabilityBoundingSet=`, acting as the **single local Composition Root and authority** (`H-010` #1): it holds the persistent `OSPP v1` WebSocket session, resolves `snow.yml` secrets/resources, materializes and supervises CoW worlds in-process, and serves as the **sole ingress for a world's `.localhost` origin** (a future tunnel-minted origin kind would still terminate at this same ingress, `H-008`). It receives explicit `--state-dir <path> --runtime-dir <path>` arguments (never guessing `$XDG_RUNTIME_DIR`) and listens for CLI RPC on `<runtime_dir>/daemon.sock` (`0600`). It adopts inherited HTTP/forward sockets from PID 1 `systemd` socket activation (`ADR-0008` §5) or binds explicit `--listen <addr>` (auto-spawned as `slipforkd --listen 127.0.0.1:0 --state-dir <path> --runtime-dir <path>` by the thin `slipfork` CLI when `<runtime_dir>/daemon.sock` is absent).
     - **Planned Static Forward Port (`H-008`, `H-006`, `ADR-0008` §5, future `0.2.0+`):** `slipforkd` already exposes a dedicated loopback `forward_port` (default `7080`, strictly distinct from `:80` and validated by `UnitSpec::validate` against `EdgeError::UnitPortCollision`) for daemon-owned `forward` bridges. If a future release adds a tunnel-minted origin kind, `WorldRegistry` will pass `local_port: planned_port` in the registration request and `weaved` will forward the public hostname to `127.0.0.1:<planned_port>`, **never** to `*.localhost` (which would redirect-loop) and **never** directly into a world netns; that origin kind will be minted from the lease's public URL **before** materialization so `WorldSpec.base_env` and `per_world = true` seeds receive the final origin on first boot with zero two-origin window, and `WorldRegistry` will own a public-hostname table populated on registration and cleared on unshare, release, or lease drop. Concrete `weaved` registration wire framing remains deferred until `tunnel-weaver` publishes `weaved`'s IPC spec (`H-006`).
     - **`snow.yml` `ingresses` Longest-Prefix Target Port Resolution (`H-010` #1):** For every proxied HTTP or WebSocket request on a `*.localhost` host, `slipforkd` matches the request path against the target world's `snow.yml` `ingresses` longest-prefix table (`match.prefix -> target.port`, falling back to the first declared component `internal_ports[0]` when `ingresses` is empty) and dials `WorldEngine::dial_world_tcp(&world, port)` with `Host` and `X-Forwarded-*` preserved.
     - **`*.localhost` Routing & Disjoint Rule Table (`LocalHostRoute`):** Requests with `*.localhost[:<port>]` `Host` headers follow **`http://(<snow-domain>.)?(<fork>.)?<project>.localhost[:<port>]`**, parsed by `slipfork_world::LocalHostRoute::parse(project: &ProjectSlug, snow_domains: &[&str], host_header: &str)` (`404` on unknown targets):
       - `<project>.localhost` (`0` prefix labels) -> `WorldTarget::Canonical`, `snow_domain: None`.
       - `<domain>.<project>.localhost` (`<domain> ∈ domains[].id`) -> `WorldTarget::Canonical`, `snow_domain: Some(<domain>)`.
       - `<fork>.<project>.localhost` (`<fork> ∉ domains[].id`) -> `WorldTarget::TestSlot(slot)` for `test-<u32>` or `WorldTarget::UserFork(<fork>)`, `snow_domain: None`.
       - `<domain>.<fork>.<project>.localhost` (`<domain> ∈ domains[].id`) -> `WorldTarget::TestSlot(slot)` or `WorldTarget::UserFork(<fork>)`, `snow_domain: Some(<domain>)`.
       - Fork names and `domains[].id` MUST be single lowercase DNS labels (`[a-z0-9-]`, zero dots) and MUST NOT start with `test-`; fork names MUST NOT equal any `domains[].id` (`WorldTarget::validate` + `validate_fork_name` -> `WorldError`, failing closed on malformed `test-*`, `domain.domain` collisions, IPv6 literals, and invalid ports).
     - **`*.localhost` Behaviour by Target World Origin (`H-008`, `0.1.0` normative; the second bullet is future `0.2.0+` intent):**
       - **`0.1.0`:** every attached world has exactly one origin kind, so `slipforkd` proxies HTTP and WebSocket traffic via the `ingresses` prefix table and `WorldEngine::dial_world_tcp(&world, port)`.
       - **Future, if a tunnel-minted origin kind ships:** a request on the world's `*.localhost` host would (1) be answered with **`308 Permanent Redirect`** (`Location: <public_url><path_and_query>`) for **every HTTP method** — including `snow_domain` ingresses such as `admin.<project>.localhost`, which would collapse into the single public origin — with method + body preserved per RFC 9110 §15.4.9 and the redirect written **before** any `100 Continue` or body read; and (2) an HTTP `Upgrade` / WebSocket request would be **refused closed with HTTP `421 Misdirected Request`** naming the public origin. Neither rule exists in `0.1.0`; no such origin kind can be represented.
2. **Future `0.2.0+`: sharing fixed at materialization inside `slipforkd`, a daemon-owned tunnel lease, and a gated `WeavedRegistrar` (`H-010` #1, `slipfork-world` + `slipfork-edge`; none of this exists in `0.1.0`):**
   - **Sharing would be fixed at materialization inside `slipforkd` (future):** a future `share [--stop] [--world <world>]` subcommand of `slipfork` (§3) MUST NOT mutate a live world's origin in place, because already-started processes inside the world would retain stale `BASE_URL`, `CSRF_TRUSTED_ORIGINS`, cookie, and OAuth environment values. Over `<runtime_dir>/daemon.sock` (`0600`, future `DaemonControl` share/unshare calls mapping 1:1 to registry share/unshare operations), `slipforkd` would tear down the running `WorldHandle` in-process, refresh the public URL and its public-hostname table inside `WorldRegistry` (registered against `slipforkd`'s planned static `forward_port`, failing closed with a typed no-forward-listener error when none is bound), and re-materialize a fresh world in-process from its origin-independent snapshot (`+ per_world` seeds) with the single new origin injected at boot (unsharing an already-single-origin world with no active lease would be an **idempotent success no-op**).
   - **Future pure `TunnelRegistrar` port, `<= 31`-byte service labels & daemon ownership (`H-006`, `H-008`, `ADR-0008` §6):** a future sharing surface will define an OS-free `TunnelRegistrar` capability in `crates/slipfork-world` (`register(route: &LocalHostRoute, local_port) -> Result<Box<dyn TunnelLease>, TunnelError>`, with `route.snow_domain()` required to be `None`), an opaque RAII lease (`public_url()`, `lease_id()`), and reuse today's deterministic `WeaverServiceName` derivation (`ADR-0008` §6 is normative for `SERVICE_NAME_MAX = 31` and `<prefix>-<sha256_hex12>`). Only the edge registry would hold `Arc<dyn TunnelRegistrar>`; CLI invocations would hold zero leases, while `--stop`, `drop`, `down`, or daemon exit would drop the lease and revoke the tunnel. Per closed `H-006` (`plan/HUMAN.md`), no adapter ships until `tunnel-weaver` publishes `weaved`'s IPC specification; until then there is no `TunnelRegistrar` trait, no fail-closed registrar double, and no sharing command at all in `0.1.0` (`M4.1` is the re-entry point).
3. **Canonical VCS `ProjectSlug` Discovery (`0.1.0`), Reconciled `world_id` & `--world` Selector Contract (`M3.25`), `RepoRootResolver`, `slipfork shell [--world <world>]`, `git-remote-slipfork`, and `trait VcsWorkspace` (`Git` + `Jujutsu`):**
   - **Canonical VCS root & `ProjectSlug` precedence (`H-005`, `RepoRootResolver` in `crates/slipfork-vcs`):**
     - **Git (`git rev-parse`):** Uses `git rev-parse --show-toplevel` as the authoritative worktree root (**never** deriving a repository root or slug from `--git-common-dir` basename). Linked `.worktrees/<fork>` checkouts (where `--git-common-dir` basename is `.git` and `<toplevel>/.git` is a file) resolve `<vcs_root>` to `--git-common-dir`'s parent (never probing worktree-local `.worktrees/<fork>/slipfork.toml`). Fails closed for bare repositories (pointing to `git clone`, since bare stores have no worktree or `slipfork.toml`), git submodules (`--show-superproject-working-tree` non-empty), and `--separate-git-dir` layouts (naming the detected topology and the `project = "<slug>"` override in `<vcs_root>/slipfork.toml`).
     - **Jujutsu (`0.1.0` `jj root` adapter, before M2 `JjWorkspaceAdapter`):** Invokes `jj root` only when `jj` is on `PATH` (zero `.jj/repo` internal parsing), failing closed with a `project = "<slug>"` hint when `jj` is absent; `.worktrees/<fork>` under `jj` should set `project = "<slug>"` in `slipfork.toml` until M2's `JjWorkspaceAdapter` lands.
     - **Precedence (`ProjectSlugOverride`):** Optional `project = "<slug>"` (`Option<ProjectSlug>`) in `<vcs_root>/slipfork.toml` (supplied to `RepoRootResolver` through the injected `ProjectSlugOverride` port implemented over `slipfork_dag::SlipforkConfig` in `slipforkd`, so `crates/slipfork-vcs` never depends on `slipfork-dag` or adds a second TOML parser) wins; otherwise `<slug>` parses `<vcs_root>`'s directory basename (`WorldError::InvalidProjectSlug` on invalid DNS labels, failing closed outside any repository).
   - **Canonical `WorldId` & `--world` Selector Reconciliation (`M3.25` target state, normative; consumed by `M3.20`, `M3.15` & `M3.9`):**
     1. **Single Typed Grammar Owner & `TestSlot` Wire Exclusion (`slipfork_world::WorldId`, signatures in `ARCHITECTURE.md` §3.4):** `WorldId` (`fmt::Display` + `std::str::FromStr` + manual JSON-string `Serialize`/`Deserialize` — never derived struct-object serde) in `crates/slipfork-world` is the **sole** owner of world-id formatting and parsing: `slipfork_edge::world_id(project, target) -> WorldId` delegates to `WorldId::from_parts`, `EngineError` world identities use typed `WorldRef { World(WorldId), SeedSlot(String), Handle(WorldHandle) }` (`ARCHITECTURE.md` §3.3), and every display table (`slipfork list` `WORLD` column), diagnostic header, `--json` `"world"` field, `WorldExecTarget.world`, and `<runtime_dir>/daemon.sock` wire `world` field (`WorldSummary`, `WorldUpSummary`, `ForwardSummary`, `BootEvent::HookFailed`, `PruneReport.worlds`, plus `WorldSelector` — shared directly by `down` and `drop_fork` and flattened into `UpRequest`, `LogsRequest`, `ExecTargetRequest`, `HookRunRequest`, and `ForwardRequest`) carries `WorldId`. `Display` formats `<project>` (`WorldTarget::Canonical`), `<project>:<fork>` (`WorldTarget::UserFork(<fork>)`, including `<project>:<project>` if a pre-existing `.worktrees/<project>` fork exists), and non-selector `<project>#test-<slot>` (`WorldTarget::TestSlot(<slot>)`, diagnostics-only for in-process `WorldRef::World` and `RoutedWorld`): ephemeral `TestSlot` pool worlds are owned internally by `crates/slipfork-test`, are **excluded** from `DaemonControl::list` and `PruneReport.worlds` (`Canonical | UserFork` only), and **fail closed (`ser::Error::custom`) in `WorldId::serialize`** (`Serialize` delegates to `serializer.collect_str(self)` strictly for `Canonical | UserFork`, while `FromStr`/`Deserialize` reject reserved `test-*`), forming an exact round-trip bijection over `Canonical | UserFork` while keeping `TestSlot` diagnostics-only under `#` so **no CLI screen, stderr diagnostic, or `--json` payload ever emits a selector spelling the CLI rejects**.
     2. **Single-Parser Input Grammar, Uniform Trimming & `<project>:<project>` Disambiguation (`WorldId::from_str` -> `WorldId::parse_selector` -> `project::resolve_world_selector`, signatures in `ARCHITECTURE.md` §3.4):** At the CLI boundary, `project::resolve_world_selector` (`crates/slipfork::project`, `M3.15`) delegates to `WorldId::parse_selector` against `RepoRootResolver::resolve(&cwd)` before sending `Option<WorldId>` over `<runtime_dir>/daemon.sock`, and `DaemonService::select` in `slipforkd` verifies `id.project() == &repo.project` against its own `RepoRootResolver::resolve(&req.cwd)` (domain-collision against `snow.yml` `domains[].id` continues to run at world boot via `LocalHostRoute::new`). **`WorldId::from_str` is the single owner of `':'` splitting:** it trims leading/trailing ASCII whitespace once (`let s = raw.trim();`; empty `s` or any embedded ASCII whitespace fails closed naming `<project>`, `<project>:<fork>`, and `<fork>`), splits single `':'` into `ProjectSlug::parse(<project>)` + `validate_fork_name(<fork>, &[])` -> `WorldTarget::UserFork(<fork>)` (rejecting empty halves, multiple `':'`, invalid DNS labels, and reserved `test-*`), and without `':'` parses `ProjectSlug::parse(s)` -> `WorldTarget::Canonical`. **`WorldId::parse_selector(raw, current_project)` trims once (`let s = raw.trim();`) and branches without re-implementing `':'` splitting:**
        - **Qualified `<project>:<fork>` or canonical `<project>` (`s.contains(':') || s == current_project.as_str()`):** delegates directly to `s.parse::<WorldId>()` (`WorldId::from_str`) and verifies `id.project() == current_project` — failing closed on cross-project mismatch (`WorldError::CrossProjectWorld`: `"world '<project>:<fork>' belongs to project '<project>', while current directory belongs to '<repo.project>'; cd into '<project>' (see WORKTREE in \`slipfork list\`) or pass \`slipfork exec --cwd <worktree> --world <project>:<fork>\`"`) — yielding `WorldTarget::UserFork(<fork>)` (`worktree = <vcs_root>/.worktrees/<fork>`) when `':'` is present or `WorldTarget::Canonical` (`worktree = repo.vcs_root`, even when `cwd` is inside `.worktrees/<fork>`) when `s == current_project.as_str()`. **Collision rule:** `<project>:<project>` is **accepted** by `FromStr` and `parse_selector` as `WorldTarget::UserFork(<project>)` (disambiguated by `':'` from bare `<project>`), so any pre-existing `.worktrees/<project>` fork printed as `<project>:<project>` remains selectable and droppable, while `slipfork fork <fork>` refuses creating a **new** fork with `<fork> == repo.project.as_str()` (advising a distinct fork name).
        - **Bare `<fork>` (no `':'` and `s != current_project.as_str()`, accepted **only** on input via `WorldId::parse_selector`):** validates `s` via `validate_fork_name(s, &[])` (failing closed on empty/whitespace/invalid DNS labels or reserved `test-*`) and returns `WorldId::from_parts(current_project.clone(), WorldTarget::UserFork(s.to_owned()))` (`worktree = <vcs_root>/.worktrees/<fork>`), preserving repo-local CLI ergonomics, hook rescue commands, and `@slipfork/opencode`'s `slipfork exec --world <fork> --cwd <cwd>`.
        - **Single selector route for `drop` vs bare creation for `fork` (`M3.20`, `M3.15`):** `slipfork drop` (`slipfork drop [<world>]` or `--world <world>`, mutually exclusive; `DaemonControl::drop_fork(&WorldSelector)`) routes any supplied selector through the **exact same** `project::resolve_world_selector` / `WorldId::parse_selector` (zero private parse path; `DaemonService::drop_fork` refuses `WorldTarget::Canonical` naming `slipfork down`), whereas fork creation `slipfork fork <fork>` trims ASCII whitespace (`fork.trim()`) and requires a new bare `<fork>` (`validate_fork_name(fork, &[])` + `fork != repo.project.as_str()`, rejecting `':'` with `"pass bare '<fork>' to \`slipfork fork\`"`). Omitting the selector (`None`) resolves `cwd`'s nearest ancestor (`.worktrees/<fork>[/...]` -> `UserFork(<fork>)`, repo root -> `Canonical`, outside any repo -> fail closed naming `cd <repo>` or `slipfork exec --cwd <repo>`).
   - **M2 Interactive Shells, `refs/slipfork/<fork>/wip` & `VcsWorkspace`:** `slipfork shell [--world <world>]` enters the selected world's mounted workspace and isolated CoW world. Because Git's D/F refname lock forbids `refs/heads/<fork>` and `refs/heads/<fork>/wip` from coexisting (`files` and `reftable` alike), the committed branch stays `refs/heads/<fork>` while the synthesized dirty view lives at **`refs/slipfork/<fork>/wip`** (fetched explicitly via `git fetch slipfork '+refs/slipfork/<fork>/wip:refs/slipfork/<fork>/wip'`). When the working tree is clean, `refs/slipfork/<fork>/wip` points directly at the `refs/heads/<fork>` base commit OID (so `wip == base` when clean); when dirty, `GitWorktreeAdapter` synthesizes a snapshot commit via scratch `GIT_INDEX_FILE` (`.slipfork/git/index-<fork>`) into `refs/slipfork/<fork>/wip` without touching `.git/index`, and `JjWorkspaceAdapter` (`jj workspace add/forget`) exports `@-` as `refs/heads/<fork>` and `@` as `refs/slipfork/<fork>/wip` (collapsing to `@-` when `@` is empty), verified against shared `assert_vcs_workspace_conformance`.

## Consequences

- Every world has at most one canonical origin known before boot — with `slipforkd` serving as the sole loop-free ingress for the `.localhost` origin (and, in a future release, a single tunnel-minted one) — eliminating split-brain cookies/CSRF/OAuth URLs, baked-in snapshot URL leaks, and OSPP startup coupling.
