# ADR-0005: Port-80 `*.localhost` Edge Daemon (`slipforkd`), Tunnel Weaver IPC (`weaved`), and `VcsWorkspace` (`git-remote-slipfork` + `jj`)

- **Status:** Accepted (normative specification for `.localhost` hostname routing, `ProjectSlug` / `WorldTarget` / fork-naming invariants, and daemon-owned `TunnelLease` lifecycle; `H-005` & `H-006` validated)
- **Date:** 2026-11-14

## Context

1. **External wildcard DNS services (such as `.nip.io`) fail offline and under DNS-rebinding filters:** Relying on public wildcard DNS leaks project hostnames and breaks on airplane Wi-Fi or corporate resolvers. Meanwhile, RFC 6761 reserves `*.localhost` for loopback resolution (`127.0.0.1` / `::1`) natively in Linux (`nss-myhostname`, `systemd-resolved`) and modern browsers (Chromium/Firefox treat `*.localhost` as a Secure Context without self-signed CA ceremony).
2. **Public tunnel sharing must not hard-link external crates or leave orphaned routes:** Developers occasionally expose a local or agent-forked world externally via **Tunnel Weaver (`weaved`)**. Compiling `weaved` into `slipfork` would tangle release cycles and credentials, while fire-and-forget tunnel registration without a single daemon lease owner leaves stale public routes when worlds stop.
3. **Working with isolated agent workspaces requires zero-`cd` shell entry, zero-patch inspection of dirty trees, and Jujutsu (`jj`) parity:** Developers on the canonical checkout want to enter a fork's shell (`slipfork shell <fork>`) or pull/diff an agent's committed *or uncommitted* edits (`git pull slipfork <fork>`, `git fetch slipfork <fork>/wip`), and repositories using **Jujutsu (`jj`)** cannot have raw `git worktree` invoked behind `.jj`'s back.

## Decision

> This ADR is the single normative home for `.localhost` label routing (§1), `TunnelLease` daemon ownership & `WeavedRegistrar` gating (§2), and VCS canonical root / `ProjectSlug` discovery + `VcsWorkspace` (§3). `ARCHITECTURE.md` keeps only concise Rust port signatures with one-line pointers here, and `docs/design/target-dx.md` keeps only user-facing CLI examples.

1. **Port-80 `*.localhost` Edge Proxy (`slipforkd` + `LocalHostRoute` + `WorldEngine::dial_world_tcp`):**
   - `slipforkd` binds `127.0.0.1:80` and `[::1]:80` (via systemd socket activation or `net.ipv4.ip_unprivileged_port_start=80`, failing closed in `slipfork doctor` / `slipfork up` with actionable setup steps if port 80 is unavailable — never falling back silently to random ports).
   - Hostnames follow **`http://(<snow-domain>.)?(<fork>.)?<project>.localhost`** (where `<project>` is a validated `slipfork_world::ProjectSlug`: `1..=63` lowercase ASCII `[a-z0-9-]`, no leading/trailing `-`), are parsed by `slipfork_world::LocalHostRoute::parse(project: &ProjectSlug, snow_domains: &[&str], host_header: &str)`, looked up in `WorldRegistry` (returning HTTP `404` on unknown targets), and forwarded into the world via `WorldEngine::dial_world_tcp(&world, port)` without branching on engine kind:
     - `<project>.localhost` (`0` prefix labels) -> `WorldTarget::Canonical`, default ingress (`snow_domain: None`).
     - `<domain>.<project>.localhost` (`1` prefix label, `<domain> ∈ domains[].id`) -> `WorldTarget::Canonical`, `snow_domain: Some(<domain>)`.
     - `<fork>.<project>.localhost` (`1` prefix label, `<fork> ∉ domains[].id`) -> `WorldTarget::TestSlot(slot)` for `test-<u32>` or validated `WorldTarget::UserFork(<fork>)`, default ingress.
     - `<domain>.<fork>.<project>.localhost` (`2` prefix labels, `<domain> ∈ domains[].id`) -> `WorldTarget::TestSlot(slot)` or validated `WorldTarget::UserFork(<fork>)`, `snow_domain: Some(<domain>)`.
   - **Single Rule Table (`WorldTarget::validate(&[&str])` + `validate_fork_name` -> `WorldError`):**
     - User fork names MUST be single lowercase DNS labels (`[a-z0-9-]`, **zero dots**), MUST NOT equal any `snow.yml` `domains[].id`, and MUST NOT start with `test-` (reserved exclusively for `TestSlot(u32)`). `domains[].id` likewise MUST NOT start with `test-`, so no declared domain can shadow slot routing.
     - `LocalHostRoute::parse`, `ResourceCoordinates::local_for_world`, and `WorldTarget::validate` all funnel through this single rule table (with `slipfork_world::WorldError` as the sole fork/slug error type, wrapped via `#[from]` in `SnowError`): non-numeric or overflowing `test-*` labels (such as `test-feat`), `domain.domain` collisions (`admin.admin`), IPv6 literals, and malformed/repeated ports all parse fail-closed to `None` (never yielding an unroutable `UserFork("test-feat")`).
2. **Daemon-Owned Tunnel Leases & Gated `WeavedRegistrar` (`slipfork-world` + `slipfork-edge`):**
   - Zero crate or binary linking between Slipfork and Tunnel Weaver, zero invented wire contract, and zero no-op fallback registrars.
   - `crates/slipfork-world` defines pure domain traits with **zero** OS socket/FD types, JSON payloads, or socket paths: `TunnelRegistrar::register(&TunnelRequest { route: &LocalHostRoute, local_port }) -> Result<Box<dyn TunnelLease>, TunnelError>`, where `TunnelLease: Send + Sync` is an opaque RAII handle exposing only `public_url()` and `lease_id()`.
   - **Daemon-owned lease lifecycle (`WorldRegistry` + `trait DaemonControl`):** The Composition Root injects `Arc<dyn TunnelRegistrar>` **only** into `slipfork_edge::WorldRegistry` inside `slipforkd`. `WorldRegistry` stores `Box<dyn TunnelLease>` per `(ProjectSlug, WorldTarget)` through its `DaemonControl` implementation (`register_tunnel(&TunnelRequest<'_>)` / `release_tunnel`). `slipfork share` and `slipfork share --stop` are thin clients of **Slipfork's own internal `slipforkd` control IPC** (`trait DaemonControl`), holding **no** `TunnelLease` themselves — exiting the CLI leaves the tunnel up, while `--stop`, `slipfork drop`, `slipfork down`, or stopping `slipforkd` drops the stored `Box<dyn TunnelLease>`.
   - **Adapter gated on a real external spec (`H-006`) & `Drop` obligation:** The concrete `WeavedRegistrar` wire adapter is deferred until `tunnel-weaver` publishes `weaved`'s actual IPC specification (version negotiation, socket path, and disconnect/revocation semantics). Until then only the traits plus `conformance::assert_tunnel_registrar_conformance` (exercised by an in-memory fake) exist. A production `TunnelRegistrar` adapter must revoke its tunnel when `TunnelLease` is dropped (the concrete mechanism is defined by `weaved`'s published spec); an unreachable daemon fails closed (`TunnelError::DaemonUnavailable`).
   - **Shared conformance:** every `TunnelRegistrar` implementation must pass `assert_tunnel_registrar_conformance` (non-empty URL/ids, unique concurrent leases, host-aware URLs, independent lease lifetimes) before it ships.
3. **Canonical VCS `ProjectSlug` Discovery (`0.1.0`), `slipfork shell [<fork>]`, `git-remote-slipfork`, and `trait VcsWorkspace` (`Git` + `Jujutsu`):**
   - **Canonical VCS root & `ProjectSlug` precedence (`H-005`, sole normative specification):**
     - **Git (`git rev-parse`):** Uses `git rev-parse --show-toplevel` as the authoritative worktree root (**never** deriving a repository root or slug from `--git-common-dir`'s own basename). Linked `.worktrees/<fork>` checkouts — where `--git-common-dir`'s basename is `.git` and `<toplevel>/.git` is a file — resolve `<vcs_root>` to `--git-common-dir`'s parent directory (and **never** probe worktree-local `.worktrees/<fork>/slipfork.toml`). Slipfork **fails closed** (never guessing) for: (a) **bare repositories** (`--is-bare-repository` = `true`, or outside a working tree), (b) **git submodules** (`--show-superproject-working-tree` non-empty), and (c) **`--separate-git-dir` layouts** (`--show-toplevel` is not the parent of `.git` and is not a linked worktree whose `--git-common-dir` basename is `.git`); every refusal names the exact topology detected and points to the `project = "<slug>"` override in `<vcs_root>/slipfork.toml` (honored on `<toplevel>/slipfork.toml` when a working tree exists).
     - **Jujutsu (`0.1.0` `jj root` adapter, before M2 `JjWorkspaceAdapter`):** Thin subprocess adapter over `jj root` executed **only** when `jj` is on `PATH`, verified deterministically in tests with a fake `jj` executable on `PATH` (**zero** `.jj/repo` internal layout/pointer parsing). When `jj` is absent from `PATH` (for example in a non-colocated `.jj` checkout on a host without `jj`) and no `project = "<slug>"` override exists, Slipfork **fails closed** with an actionable message naming `project = "<slug>"` in `slipfork.toml`. Because `jj root` is workspace-scoped, set `project = "<slug>"` in `slipfork.toml` for `.worktrees/<fork>` under `jj` — otherwise the fork/workspace name is used — until M2's `JjWorkspaceAdapter` lands.
     - **Precedence:** Optional `project = "<slug>"` (`Option<ProjectSlug>`) in `<vcs_root>/slipfork.toml` wins; otherwise `<slug>` is parsed from `<vcs_root>`'s directory basename (`WorldError::InvalidProjectSlug` on invalid DNS labels, failing closed outside any repository).
   - `slipfork shell [<fork>]` opens an interactive `$SHELL` directly inside `<fork>`'s mounted workspace and isolated CoW world (or the world bound to `cwd` when `<fork>` is omitted).
   - `VcsWorkspaceFactory` inspects `repo_root` at the Composition Root and wires one of two `trait VcsWorkspace` adapters (with zero `kind()` enum on the trait):
     - `GitWorktreeAdapter`: `git worktree add/remove .worktrees/<fork>`; synthesizes `<fork>/wip` via an injected disk-backed scratch `GIT_INDEX_FILE` (`git write-tree` + `git commit-tree`) so dirty/untracked agent edits can be fetched without mutating the fork's index or `HEAD`.
     - `JjWorkspaceAdapter` (M2, when `.jj/` exists at repo root): `jj workspace add --name <fork> .worktrees/<fork>` and `jj workspace forget <fork>`, exporting Jujutsu's working-copy commit (`@`) directly as `<fork>/wip` and `@-` as `<fork>`.
   - `slipfork up` and `slipfork fork` ensure the `slipfork` Git remote (`slipfork::.`) is registered so `git pull slipfork <fork>` and `git fetch slipfork <fork>/wip` work out of the box via `git-remote-slipfork`.
   - **Shared conformance (M2):** `GitWorktreeAdapter` and `JjWorkspaceAdapter` must both pass one `assert_vcs_workspace_conformance` suite covering `create_workspace` → `export_refs` (committed `head_oid` **and** dirty-tree `wip_oid`) → `remove_workspace`, asserting the fork's live index/`HEAD` is never mutated. Neither adapter ships before the suite is green.

## Consequences

- Offline-proof, browser-secure-context `http://(<domain>.)?(<fork>.)?<project>.localhost` URLs with zero port numbers; RAII-leased public tunnels owned by `slipforkd`'s `WorldRegistry` once the gated `weaved` adapter lands; first-class `git` and `jj` agent workspace ergonomics.
