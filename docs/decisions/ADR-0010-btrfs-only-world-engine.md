# ADR-0010: Btrfs `WorldEngine` — Unified Per-World Subvolumes, `BTRFS_IOC_*` Lifecycle, `--ipc` Isolation, and AppArmor `userns`

- **Status:** Accepted — M3 (`0.1.0`) target-state ruling (owner ruling 2026-11-16; closes `H-004`; `WorldEngine` IoC contract in `ADR-0002`; implemented across `M3.20`, `M3.12`–`M3.15`, and `M3.21`)
- **Date:** 2026-11-16

## Context

1. **One atomic CoW substrate per world (`Iron Law #3`, `H-004` closed):** Each Slipfork world combines a `Dockerfile`-derived `L0` rootfs (`ADR-0009`) with mutable PostgreSQL, Redis, and S3 state that must snapshot into immutable DAG stages and clone into isolated worktree and test worlds atomically under the developer's unprivileged `$UID:$GID`, using a single `WorldEngine` (`BtrfsEngine`) with zero fallback paths.
2. **Unified-subvolume CoW in milliseconds with a small per-world RSS:** Placing a world's `ADR-0009` `Dockerfile` `L0` rootfs tree and backing-service state directories inside **one unified Btrfs subvolume** keeps read-only snapshots, writable clones, and warm-SQL boots in milliseconds at a small per-world RSS, with `$UID:$GID` host bind mounts working natively. `docs/research/btrfs-crun-benchmarks.md` is the sole owner of the measured figures.
3. **Three host and kernel invariants govern unprivileged execution:**
   - Parallel PostgreSQL instances binding `:5432` across separate network namespaces still collide on System V shared memory (`shmget` key `90000` / port-derived keys) unless each world also enters a private IPC namespace (`--ipc` / `CLONE_NEWIPC`).
   - Read-only Btrfs snapshots (`BTRFS_SUBVOL_RDONLY`) reject `BTRFS_IOC_SNAP_DESTROY_V2` until `BTRFS_SUBVOL_RDONLY` is cleared via `BTRFS_IOC_SUBVOL_SETFLAGS`, and unprivileged subvolume deletion requires `mount -o user_subvol_rm_allowed,noatime`.
   - On Ubuntu 24.04 LTS (`noble`, Linux 6.8+, AppArmor 4.0) with `kernel.apparmor_restrict_unprivileged_userns=1`, unprofiled unprivileged `CLONE_NEWUSER` transitions strip capabilities (`EPERM` on `uid_map`/`mount`/`pivot_root`) unless `/etc/apparmor.d/slipfork` grants `userns,`.

## Decision

> This ADR is the single normative home for the unified-subvolume & control-directory layout (§2), `BTRFS_IOC_*` lifecycle & snapshot GC staging (§3), fail-closed host contract, `SubvolumeDriver::probe` vs `ensure_supported` split, & `HostProbe` `doctor` seam (§4), `SubvolumeDriver` constructor-DI seam (§5), `--ipc` (`CLONE_NEWIPC`) isolation (§6), and Ubuntu 24.04 LTS AppArmor `userns` profile (§7). `ARCHITECTURE.md` keeps concise Rust port signatures and owns the Cargo Feature & Test-Scaffolding Rule (§1), `ADR-0002` owns the `WorldEngine` IoC + `ReadinessProbe` service contract, `ADR-0009` owns the `L0` rootfs + world-internal `/.slipfork/bin/crun` contract, and other ADRs reference § pointers here instead of restating layout paths, ioctls, or namespace flags.

1. **`BtrfsEngine` Is the Sole Production `WorldEngine` (`M3.20` -> `M3.12`–`M3.15` -> `M3.21`):**
   - `BtrfsEngine` — one unified Btrfs subvolume per world + Linux `userns`/`netns`/`ipcns`/`pidns`/`mntns` + `pivot_root` + daemonless static `crun` — is Slipfork's **sole** production `WorldEngine`, with distinct read-only snapshot vs writable clone method signatures, zero capability boolean bags, zero snapshot-mode flags, and zero fallback paths (`H-004` closed by owner ruling). `M3.20` aligns `trait WorldEngine` ahead of `M3.12`–`M3.15`, and `M3.21` deletes all previously shipped engine adapters, their daemon/REST protocol, their storage pools, and every per-file extent-clone helper once `BtrfsEngine` lands (`M3.12`–`M3.15`); no fallback engine and no runtime engine selection exists.
2. **Unified Single-Subvolume World Layout, `BaseKey::derive`, `BaseImageBuilder` vs `BtrfsEngine` Boundary & Disjoint Control/Socket Directories:**
   - Every materialized world and snapshot (`<project>-base-<base_key_sha12>`, origin-independent `[fixtures.*]` snapshots, `canonical`, `<fork>`, `test-<slot>`) is **exactly one Btrfs subvolume** (`<state_dir>/snapshots/<snapshot_id>` when sealed read-only; `<state_dir>/worlds/<world_id>` when live writable) holding **both** the `ADR-0009` `Dockerfile`-derived `L0` rootfs tree (`<subvol>/rootfs`, mounted read-only `EROFS` at `/`) **and** `/var/lib/slipfork/state/{pgdata,redis,s3}` (`<subvol>/state/{pgdata,redis,s3}`, mounted read-write into `crun` backing-service containers). Pure `BaseKey::derive` in `crates/slipfork-engine` (`M3.13` target state, `ARCHITECTURE.md` §3.3) is the single owner computing `base_key_sha12` (first 12 lowercase hex digits of SHA-256 over `"slipfork-base:v2\0"`, `project`, `WorldRootfs.digest`, sorted `BackingServiceKey`/`OciRootfs.digest` pairs, and sorted `pg_databases` `BaseSeedSource::tag` `"clean"` | `<dump_sha256>`) and mapping `BaseKey::snapshot_id() -> SnapshotId` (`<project>-base-<base_key_sha12>`).
   - **Strict `BaseImageBuilder` vs `BtrfsEngine` boundary (`M3.8`, `M3.20`, `M3.13`):** `BaseImageBuilder` (`DockerfileStageBuilder`, `ADR-0009`) materializes plain content-addressed directories under `<state_dir>/cache/{rootfs,oci}` and holds **no** `SubvolumeDriver`. Seeding transient `<state_dir>/worlds/seed-<base_key_sha12>` from `cache/rootfs/<l0_merkle_sha256>/app` via `WorldEngine::ensure_base(&BaseSeedSpec)` (`ARCHITECTURE.md` §3.3; sole production impl `BtrfsEngine`, so `slipforkd` holds only `Arc<dyn WorldEngine>`), sealing the read-only base subvolume `<state_dir>/snapshots/<project>-base-<base_key_sha12>`, and destroying the transient seed subvolume belong **exclusively** to `BtrfsEngine` (`M3.13`).
   - **No nested child subvolumes inside a world:** Because `BTRFS_IOC_SNAP_CREATE_V2` does not snapshot nested subvolumes recursively, everything inside `<subvol>` is plain directories and CoW-shared extents within that single subvolume, so **one ioctl** snapshots or clones the entire world atomically.
   - **Three non-overlapping control/socket paths (normative):**
     1. **Daemon-wide control socket directory (`--runtime-dir` = `<runtime_dir>`):** passed explicitly to `slipforkd` (resolved once at the thin `slipfork` CLI composition boundary via `Layout::resolve`, `ARCHITECTURE.md` §1 / `ADR-0008` §4; `slipforkd` never defaults or guesses it), holding `<runtime_dir>/daemon.sock` (`0600`).
     2. **Daemon-wide HTTP ingress Unix socket:** `<state_dir>/http-ingress.sock` (`0600`).
     3. **Per-world ephemeral control directory (`WorldSpec.control_dir` = `<state_dir>/ctl/<world_id>`, and `BaseSeedSpec.control_dir` = `<state_dir>/ctl/seed-<base_key_sha12>` during seeding):** injected explicitly by `slipforkd` (never re-derived inside `BtrfsEngine` and strictly disjoint from `<runtime_dir>`), holding `netns.sock` (`0600`), `world-init.json` (`0600`), `init.ready`, `oci/`, `oci-run/`, `mountpoints/`, and `merged/` **outside** `<subvol>` so `freeze_world` never captures ephemeral sockets or OCI runtime state.
3. **Normative `BTRFS_IOC_*` Lifecycle (`<linux/btrfs.h>`, target state `M3.12`–`M3.13` & Phase 2 `M3.2`):**
   - **Base subvolume creation:** `BTRFS_IOC_SUBVOL_CREATE_V2` (`flags = 0`, `struct btrfs_ioctl_vol_args_v2`) on the parent directory descriptor (`O_RDONLY | O_DIRECTORY | O_CLOEXEC`).
   - **Read-only snapshot (`create_snapshot` / `freeze_world`):** `freeze_world` stops `WorldProcess` services first, then `OciContainer` services (`SIGTERM` -> bounded grace), and seals `<subvol>` into `<state_dir>/snapshots/<id>` via `BTRFS_IOC_SNAP_CREATE_V2` with `flags = BTRFS_SUBVOL_RDONLY` (`1ULL << 1`).
   - **Writable world clone (`clone_world`):** Clones `<state_dir>/snapshots/<id>` into `<state_dir>/worlds/<world_id>` via `BTRFS_IOC_SNAP_CREATE_V2` with `flags = 0`. Read-only snapshot and writable clone are distinct method signatures — no mode enum exists.
   - **Teardown & staged snapshot/cache GC (`destroy_world` / `slipfork prune`):** `destroy_world` reaps the world's PID 1 namespace, removes `<control_dir>`, and calls `SubvolumeDriver::destroy_subvolume`, which reads subvolume flags (`BTRFS_IOC_SUBVOL_GETFLAGS`), clears `BTRFS_SUBVOL_RDONLY` via `BTRFS_IOC_SUBVOL_SETFLAGS` (`flags & !BTRFS_SUBVOL_RDONLY`) when set, and removes the subvolume via `BTRFS_IOC_SNAP_DESTROY_V2` (clearing RO is owned internally by `destroy_subvolume`, with no separate boolean mode switch). `BtrfsEngine` serializes base seeding under `flock` on `<state_dir>/worlds/.seed.lock` and excludes `seed-*` / `.seed.lock` from world-orphan enumeration. In M3 Phase 1 (`M3.13`–`M3.15`, `M3.19`), `DaemonControl::prune` reaps only attached world records whose checkout is gone (`PruneReport.snapshots` remains empty), and `slipfork prune` human output **explicitly prints a retention line** stating that sealed `<state_dir>/snapshots/*` bases and `<state_dir>/cache/{rootfs,oci}` entries are retained in Phase 1 so a snapshot no-op is never silent; in M3 Phase 2 (`M3.2` target state, `M3.2.13`), **`DaemonService::prune` in `slipforkd` is the sole retention owner**: each surviving attached live world record, in-flight `BaseSeedSpec` / `M3.2` `WorldPool` lease, and active `DigestCache` lineage root retains its `BaseKey` inside `DaemonService`, and `DaemonService::prune` inserts every retained `base_key.snapshot_id()` into `snapshot_keep: BTreeSet<SnapshotId>` (alongside surviving `WorldSpec.snapshot` and `DigestCache`-referenced stage/fixture `SnapshotId`s so sealed bases are typed members of `snapshot_keep` — retained bases are protected and superseded bases are collected), populates `CacheKeepSet` from every surviving live world's `WorldSpec.rootfs` (`WorldRootfs.digest` + `WorldRootfs.service_images[..].digest`, so running `crun` containers never lose their mounted `cache/oci/<sha256>/rootfs`) plus every retained `BaseKey` (`rootfs_digest` + `oci_digests`), computes referenced artifact digests `BTreeSet<String>`, and delegates each storage class exclusively through its owning port (`WorldEngine::prune_snapshots` for `<state_dir>/snapshots/*` and `BaseImageBuilder::prune_cache` for `<state_dir>/cache/{rootfs,oci}` in `ARCHITECTURE.md` §3.3, and `ArtifactStore::prune_artifacts` for `<state_dir>/artifacts/*` in `ARCHITECTURE.md` §3.6; `<state_dir>/cache/runtime/` retention is specified once in `ARCHITECTURE.md` §3.3).
4. **Fail-Closed Host Contract, `ensure_supported` vs `probe` Ownership, and `HostProbe` `doctor` Seam (`BTRFS_SUPER_MAGIC = 0x9123683e`, target state `M3.12`/`M3.15`, `M3.25`):**
   - **Single Btrfs probe owner & exact split between `ensure_supported`, `probe`, and `destroy_subvolume`:** `crates/slipfork-engine::btrfs` is the **sole owner** of Btrfs filesystem and ioctl probing behind `SubvolumeDriver` (`KernelBtrfsDriver` in production, `BTRFS_MOUNT_HINT`, and injected `btrfs::probe_with` with zero internal `KernelBtrfsDriver` construction and zero duplicated `statfs` or ioctl code; Rust signatures in `ARCHITECTURE.md` §3.3):
     1. **`SubvolumeDriver::ensure_supported` (`slipforkd` boot owner):** called by `BtrfsEngine::with_driver` at `slipforkd` startup after `slipforkd` ensures `<state_dir>` exists and before any snapshot or world directory exists. `ensure_supported` is **magic-only**: it inspects `statfs(path)` and fails closed with `EngineError::BtrfsRequired { path, actual_fstype, mount_hint: BTRFS_MOUNT_HINT }` when `f_type != BTRFS_SUPER_MAGIC` (`0x9123683e`). It does **not** execute a scratch-subvolume round-trip and does **not** prove `user_subvol_rm_allowed` or `noatime` at daemon boot.
     2. **`SubvolumeDriver::probe` (`slipfork doctor` pre-daemon owner):** called via `btrfs::probe_with` inside `slipfork::doctor::run` (holding **no** `WorldEngine`, so `doctor` runs when `slipforkd` refuses to boot and stays conformance-testable via `ARCHITECTURE.md` §1 test doubles). `probe` inspects `statfs`/`statvfs` on `probed_path` (`path` or its nearest existing ancestor, creating nothing on non-Btrfs hosts and returning `Ok(BtrfsProbeReport { btrfs_super_magic: false, user_subvol_rm_allowed: None, .. })`) and — **only when `btrfs_super_magic` is `true`** — creates `path` if needed and executes a live scratch subvolume create -> RO snapshot -> clear-RO -> `BTRFS_IOC_SNAP_DESTROY_V2` round-trip under `<state_dir>/.doctor-probe-<pid>` (outside `worlds/` and `snapshots/`); on every intermediate failure path, `probe` best-effort clears RO / destroys any created scratch snapshot and subvolume and removes `<state_dir>/.doctor-probe-<pid>` before returning, leaving zero uncollected probe residue.
     3. **`SubvolumeDriver::destroy_subvolume` -> `EngineError::SubvolumeDestroyDenied` (runtime enforcement when `doctor` was skipped):** if `slipforkd` boots on a Btrfs mount lacking `user_subvol_rm_allowed`, `ensure_supported` passes (`BTRFS_SUPER_MAGIC` matches) and the first unprivileged `BTRFS_IOC_SUBVOL_SETFLAGS` / `BTRFS_IOC_SNAP_DESTROY_V2` failure with `EPERM` (transient base-seed cleanup in `M3.13`, `destroy_world`, or `prune`) returns typed `EngineError::SubvolumeDestroyDenied { path, errno, mount_hint: BTRFS_MOUNT_HINT }` (`M3.12`, sharing `BTRFS_MOUNT_HINT` without misreporting `actual_fstype`, while other driver ioctl/statfs failures map to `EngineError::Ioctl { op, path, errno }`, `ARCHITECTURE.md` §3.3). Zero probe-and-degrade paths exist.
   - **`BtrfsProbeReport` shape (normative, specified once here; consumed by `M3.12` & `M3.15`):**
     - `state_dir: PathBuf` — requested state directory path;
     - `probed_path: PathBuf` — existing directory (`state_dir` or nearest existing ancestor) inspected by `statfs`/`statvfs`;
     - `fstype: i64` — raw `statfs(probed_path).f_type` code;
     - `btrfs_super_magic: bool` — `fstype == BTRFS_SUPER_MAGIC` (`0x9123683e`);
     - `user_subvol_rm_allowed: Option<Result<(), i32>>` — `None` when `!btrfs_super_magic` (nothing created), `Some(Ok(()))` when item 2's scratch round-trip succeeds, or `Some(Err(errno))` recording the raw kernel ioctl `errno` (e.g. `libc::EPERM` when `user_subvol_rm_allowed` is absent);
     - `noatime: bool` — `statvfs(probed_path)` `ST_NOATIME` mount-option evidence (**advisory only**: `noatime == false` is excluded from both `DoctorReport.ok` and `DoctorReport.fixes`, so missing `noatime` never fails `doctor` and never breaks `fixes.is_empty() <=> ok == true`).
   - **`HostProbe` & `DoctorReport` for pre-daemon namespace diagnostics (`crates/slipfork::doctor`, `M3.25`, consumed by `M3.15` & `M3.9`; Rust signatures in `ARCHITECTURE.md` §3.3):**
     - Alongside `&dyn SubvolumeDriver`, `crates/slipfork::doctor` (`#![forbid(unsafe_code)]`) owns `HostProbe`, two-variant `HostCheckOutcome` (zero `Skipped` variant on `HostProbe`), `NetnsCheck` (`Skipped` synthesized **solely** by `doctor::run` when `unshare_userns != Ok`), and `DoctorReport` (Rust signatures in `ARCHITECTURE.md` §3.3), with one production adapter `OsHostProbe` constructed in `crates/slipfork/src/main.rs` and injected into `doctor::run` (never into `slipforkd` boot; world boot surfaces `unshare` denial via `EngineError::UsernsDenied` from `BtrfsEngine`, and both `BtrfsEngine` [`world_init_bin` parent, `M3.13`] and `OsHostProbe::probe_userns` [`current_exe()` parent, `M3.15`] call `slipfork_engine::userns_remediation_hint` in `ARCHITECTURE.md` §3.3). Both `OsHostProbe` probes run with `env_clear()` + `PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin` + `LC_ALL=C` + `LANGUAGE=C` (never conflating subprocess exit codes with POSIX `errno`): `probe_userns` runs `unshare --user --map-user=<uid> --map-group=<gid> -- true` (`install util-linux` `hint` when `unshare` is missing; `userns_remediation_hint` on `"Operation not permitted"`), and when `probe_userns == Ok`, `probe_netns` runs `unshare --user --map-user=<uid> --map-group=<gid> --keep-caps --net --ipc --pid --fork -- ip link set lo up` (`install iproute2` `hint` when `ip` is missing).
     - **Zero host `crun` probe in `doctor` (`ADR-0009` §1, `M3.25`):** Static `crun` is a world-rootfs asset (`ADR-0009` §1), never a host `PATH` prerequisite; `doctor` performs **no** host `crun` probe and emits **no** `crun` field (`M3.9`, `M3.15`).
     - **Single owner per `doctor` output & normative text/`--json` projection from `DoctorReport` (`M3.15`, `M3.9`):** `crates/slipfork::doctor` computes `DoctorReport.filesystem` from `btrfs.fstype` (`0x9123683e => "btrfs"`, `0x58465342 => "xfs"`, `0xef53 => "ext4"`, `0x01021994 => "tmpfs"`, `0x794c7630 => "overlayfs"`, else `"unknown(0x<hex>)"`), renders human text lines (`state_dir`, `filesystem`, `btrfs_super_magic: ok|mismatch`, `subvolume_ioctl: ok|skipped|failed (errno <n>)`, `noatime: ok|missing`, `unshare_userns: ok|failed`, `netns: ok|skipped|failed`), and projects `DoctorReport` into `--json` by (a) flattening `btrfs.{state_dir,probed_path,fstype,btrfs_super_magic,noatime}` (`fstype` formatted `"0x<lowercase-hex>"`) to top-level keys alongside `ok`, `uid`, `gid`, `filesystem`, `unshare_userns`, `netns`, and `fixes`, (b) renaming `btrfs.user_subvol_rm_allowed` to top-level `"subvolume_ioctl"` (`None => { "status": "skipped" }`, `Some(Ok(())) => { "status": "ok" }`, `Some(Err(errno)) => { "status": "failed", "errno": errno, "hint": BTRFS_MOUNT_HINT }`), and (c) populating `DoctorReport.fixes` in the fixed deterministic emission order **`btrfs` -> `unshare_userns` -> `netns`** — 1. `slipfork_engine::btrfs::BTRFS_MOUNT_HINT` appended once when `!btrfs_super_magic` or `user_subvol_rm_allowed == Some(Err(_))` (also supplying `subvolume_ioctl.hint` on `Some(Err(_))`; `BtrfsProbeReport` carries no hint field, and advisory `noatime == false` adds nothing to `fixes`), 2. `unshare_userns` `Failed.hint` when `Some`, 3. `netns` `Executed(Failed { hint: Some(..), .. })`: `{ "ok": bool, "uid": u32, "gid": u32, "state_dir": str, "probed_path": str, "fstype": "0x<lowercase-hex>", "filesystem": str, "btrfs_super_magic": bool, "subvolume_ioctl": { "status": "ok"|"skipped"|"failed", "errno"?: i32, "hint"?: str }, "noatime": bool, "unshare_userns": { "status": "ok"|"failed", "detail"?: str, "hint"?: str }, "netns": { "status": "ok"|"skipped"|"failed", "detail"?: str, "hint"?: str }, "fixes": [str] }`, exiting `0` iff `DoctorReport.ok == true` (`btrfs_super_magic && user_subvol_rm_allowed == Some(Ok(())) && unshare_userns == Ok && netns == Executed(Ok)`, with `fixes` empty iff `ok == true`) and `1` otherwise (all pre-`0.3.0` `doctor` JSON keys are deleted).
5. **Injected `SubvolumeDriver` Constructor-DI Seam (`M3.12`–`M3.15`):**
   - `crates/slipfork-engine::btrfs` defines `pub trait SubvolumeDriver: Send + Sync` (method signatures in `ARCHITECTURE.md` §3.3) as the **sole** CoW subvolume cloning seam across the workspace — shared via `Arc<dyn SubvolumeDriver>` by `BtrfsEngine` and M3 Phase 2's `BtrfsArtifactStore` (`crates/slipfork-test`, `M3.2`, `<state_dir>/artifacts/<digest>`), with no second artifact-cloning driver port alongside it.
   - **`KernelBtrfsDriver`** is the **only** production implementation (all `statfs` and `BTRFS_IOC_*` `unsafe` calls live in `crates/slipfork-engine/src/btrfs.rs` with per-call `// SAFETY:` proofs). `BtrfsEngine::new(...)` wires `Arc::new(KernelBtrfsDriver)` into the explicit DI constructor `BtrfsEngine::with_driver(..., Arc<dyn SubvolumeDriver>) -> Result<Self, EngineError>`.
   - **Test-only drivers (`TestTreeDriver`):** Governed by the single normative Cargo Feature & Test-Scaffolding Rule in `ARCHITECTURE.md` §1; real kernel verification runs in `critical_btrfs_live` (`M3.14`, `M3.15`, `M3.19`).
6. **Normative `--ipc` (`CLONE_NEWIPC`) World Isolation & Supervisor Lifeline (target state `M3.13`):**
   - `slipfork-world-init` is spawned via `unshare --user --map-user=$UID --map-group=$GID --keep-caps --mount --net --ipc --pid --fork --kill-child=SIGKILL --mount-proc` with a piped `O_CLOEXEC` `stdin` lifeline (closed on `destroy_world`, `BtrfsEngine` drop, or `slipforkd` exit so PID 1 observes `EOF` and exits `0` without hitting unhandled-`SIGTERM` `SIGNAL_UNKILLABLE` drops), and `nsenter` enters `--ipc` alongside `--user --preserve-credentials --mount --net --pid`.
   - `--ipc` (`CLONE_NEWIPC`) isolates System V shared memory (`shmget`) and POSIX message queues per world so parallel `postgres` containers never collide on SysV IPC key `90000` or port-derived keys.
7. **Ubuntu 24.04 LTS AppArmor `userns` Profile (`slipfork daemon unit --only apparmor`, `M3.15`):**
   - Alongside `slipforkd.socket` and `slipforkd.service`, `slipfork daemon unit` (`--only socket|service|apparmor`) renders the 4-line `/etc/apparmor.d/slipfork` profile required on Ubuntu 24.04 LTS (`noble`, Linux 6.8+, AppArmor 4.0) when sysctl `kernel.apparmor_restrict_unprivileged_userns=1` is enabled (where `<rel_bin_dir>` is `<bin_dir>` stripped of leading and trailing `/`, or `slipfork{,d,-world-init}` bare when `<bin_dir>` is `/`):
     ```text
     abi <abi/4.0>,
     profile slipfork /{<rel_bin_dir>/slipfork{,d,-world-init},usr/bin/unshare,.slipfork/bin/crun} flags=(unconfined) {
       userns,
     }
     ```
   - **Kernel mechanism (`security/apparmor/{domain.c,task.c,path.c}`):** Under `kernel.apparmor_restrict_unprivileged_userns=1`, `aa_profile_ns_perm` transitions any unprivileged `CLONE_NEWUSER` caller in the built-in `unconfined` label into `unprivileged_userns` (`audit deny capability,`), denying `CAP_SYS_ADMIN` (`EPERM`), whereas a task in a named `flags=(unconfined)` profile declaring `userns,` stays in `slipfork` across `CLONE_NEWUSER` with file, mount, and network mediation inactive. On `execve`, `profile_transition` for `flags=(unconfined)` ignores file `ix` rules and runs `find_attach` against `aa_path_name` resolved in the **calling task's mount namespace** (`current->nsproxy->mnt_ns->root`): an `unconfined` caller (an auto-spawned `slipforkd` started before `apparmor_parser -r`, or a Cargo-hashed test binary with no `slipforkd` parent) transitions into `slipfork` **only** when an `execve`d binary matches `slipfork`'s attachment expression, and `BtrfsEngine::spawn_service` enters a world via `nsenter` (`setns(2)`, which preserves the caller's AppArmor `cred` label rather than inheriting `slipfork-world-init`'s) before `execve`ing `/.slipfork/bin/crun` inside the `pivot_root`ed world mount namespace (`ADR-0009` §1). AppArmor 4.0 accepts a single attachment expression per profile header, so one leading-slash `{...}` alternation names all five paths: `<bin_dir>/slipfork`, `<bin_dir>/slipforkd`, `<bin_dir>/slipfork-world-init`, host `/usr/bin/unshare` (outer world `CLONE_NEWUSER` and `doctor`), and in-world `/.slipfork/bin/crun` (inner OCI `CLONE_NEWUSER`). VM test harnesses (`tools/do_vm.py`) expand only the `<bin_dir>` clause to cover `/usr/local/bin` plus `<remote_tree>/target/{debug,release}` while keeping `,usr/bin/unshare,.slipfork/bin/crun}` and the 4-line body byte-identical (`docs/design/do-vm-harness.md` §3).
   - **Trust-boundary consequence:** Worlds are cooperative unprivileged `$UID:$GID` namespace sandboxes rather than hostile-tenant VMs, so granting `userns,` to in-world `/.slipfork/bin/crun` is strictly within `ADR-0010`'s isolation model; attaching host `/usr/bin/unshare` additionally permits any local unprivileged process on that workstation or CI VM to create a capability-bearing user namespace via `/usr/bin/unshare` (matching stock Ubuntu 24.04's `/etc/apparmor.d/{crun,runc,chrome}` `flags=(unconfined)` shims without crossing any `$UID` or host-root boundary).

## Consequences

- Unifies world and artifact CoW storage, snapshotting, cloning, and GC on Btrfs subvolumes (Context §2) with one `WorldEngine`, one `SubvolumeDriver` seam, one CLI `HostProbe` diagnostic port, zero fallback branches, and pure constructor DI (`ARCHITECTURE.md` §1); operationally, every non-Btrfs `<state_dir>` hard-fails closed at `slipforkd` boot with `EngineError::BtrfsRequired`, while `slipfork doctor` receives `Ok(BtrfsProbeReport { btrfs_super_magic: false, .. })` from `SubvolumeDriver::probe`, populates `fixes` with `BTRFS_MOUNT_HINT`, and exits `1` (§4).
