# ADR-0006: World-Owns-The-Stack Inversion, Slipfork Testing Protocol (`STP v1`) Direction, Typed `[test]` Schema, and `SLIPFORK_OUTPUT_DIR`

- **Status:** Accepted — M3 target state (`M3.13`–`M3.15`, Phase 2 `M3.2`; `STP v1` direction in §3; `ADR-0009` `crun` backing-service containers; `ADR-0010` unified per-world Btrfs subvolume snapshots & clones; `[test]` schema shipped in `0.1.0` `crates/slipfork-dag`)
- **Date:** 2026-11-16

## Context

1. **Non-Django stacks lack a cohesive full-stack test harness, while Django's harness duplicates work:**
   - Frameworks such as **Flask + Alembic**, **FastAPI**, **Node/TS (Hono, Express, SvelteKit, Next.js + Drizzle/Prisma)**, **PHP (Slim, Symfony, Laravel)**, **Go**, and **Rust (`axum` + `sqlx`)** lack a built-in equivalent of `pytest-django`'s `live_server` + migrated DB, forcing teams onto slow `testcontainers` or port-colliding setup scripts. Conversely, `pytest-django` creates `test_<db>`, runs migrations, boots WSGI threads, and runs `TRUNCATE` / `serialized_rollback` — 100% redundant inside CoW worlds.
2. **User-authored shell pipelines and hardcoded per-language Rust drivers fail from opposite ends:**
   - Asking users to assemble shard paths manually via shell env interpolation in `Forkfile` and post-suite shell recipes in `Forkfile` leaks orchestrator plumbing into user manifests and invites fragile shell quoting bugs.
   - Conversely, hardcoding per-language coverage/mutation drivers inside Slipfork's Rust core or guessing framework CLI flags ("transparent" sharding magic) couples the orchestrator to every language's internal tooling instead of keeping the Rust orchestrator language-blind.
3. **Cold process startup and repeated setup dominate Btrfs subvolume CoW:**
   - Unified Btrfs world subvolumes snapshot and clone in milliseconds (`ADR-0010` Context §2), whereas cold `postgres` initialization, cold browser launches, and repeated migration/fixture setup take seconds unless materialized setup stages freeze into reusable read-only Btrfs subvolume snapshots (`ADR-0009` + `ADR-0010` §3).

## Decision

> §1 (the Manifest Plumbing Law) and §5's typed `[test]` schema (`crates/slipfork-dag`, `0.1.0`) are shipped and binding today; §2 and §4 define M3 target-state world/engine invariants (`BtrfsEngine` + `ReadinessProbe` in `M3.13`–`M3.15`; warm `TestSlot` pool, `BtrfsArtifactStore`, and `SLIPFORK_OUTPUT_DIR` runtime mounting in `M3.2`); and §3 records the Phase 2 (`M3.2`) **`STP v1`** target state.

1. **General Manifest Law — Zero Stringly Plumbing (normative, shipped in `0.1.0`):**
   - **Slipfork configuration never contains shell pipelines, manual path assembly, or env interpolation for values the tool itself owns — if a value is needed it is a typed field, if a path is needed the tool supplies it.**
   - `Forkfile` and `Forkfile` expose zero post-suite shell hook fields and zero manual artifact-path interpolation (Iron Law #3: zero pre-`1.0` backward compatibility).
   - **Scoped Typed Surfaces:** Mode-scoped components (`modes.<mode>.components.<id>` add/remove/override in `Forkfile`, `ADR-0001` §1) and the test-scoped `[test]` table in `Forkfile` (which carries **only typed configuration fields** — no hook surface exists under `[test]`) are the sole configuration surfaces.
2. **World-Owns-The-Stack Inversion (OSPP-Independent, M3 target state `M3.13`–`M3.15` & `M3.2`):**
   - The CoW world — defined once by `Forkfile` (`resources`, `hooks: pre-deploy`, `components`, `ingresses`) plus `Forkfile` (`[artifacts]`, `[fixtures]`) — migrates PostgreSQL, seeds origin-independent snapshots under hermetic `ResourceMode::Test` defaults (`ADR-0008` §3), assigns the world's single `WorldOrigin` (`http://test-<slot>.<project>.localhost`, `ADR-0005` §1), runs any `per_world = true` steps, and boots live HTTP/worker services (verified protocol-ready via `ReadinessProbe`, `ADR-0002` §2) before tests run. **OSPP is not a prerequisite for M2 or M3** (`FileVaultProvider` + derived `.localhost` origins suffice). A `per_world = true` snapshot is never served from the world-independent snapshot cache (`CacheAction::Rebuild`), because its digest cannot encode the world whose absolute origin URLs it bakes in (`ADR-0003` §1).
   - Test suites read Slipfork-supplied `BASE_URL` (`origin.url()`) and resolved `Forkfile` env vars (`DATABASE_URL`, `REDIS_URL`, `AWS_S3_ENDPOINT_URL`) with zero `testcontainers` or `live_server` glue.
3. **Slipfork Testing Protocol (`STP v1`) & Language-Blind DAG Orchestrator (Phase 2 `M3.2` Target State — Single Normative Wire-Framing Home):**
   - **Inherited shared-FD transport & RFC 8949 CBOR wire framing (normative):** `slipfork test` (`M3.2`) communicates with testing frameworks over `STP v1` on an **inherited shared file descriptor** (`SLIPFORK_PROTOCOL_FD`, an `AF_UNIX` `SOCK_STREAM` `socketpair`). Every `STP v1` message on `SLIPFORK_PROTOCOL_FD` is serialized with **CBOR per RFC 8949**, length-framed as a **4-byte big-endian unsigned byte-length prefix (`u32` in `1..=MAX_STP_FRAME_BYTES`, where `MAX_STP_FRAME_BYTES = 16 * 1024 * 1024` / 16 MiB; any length prefix `== 0` or `> MAX_STP_FRAME_BYTES` fails closed before allocation) followed by exactly one well-formed RFC 8949 CBOR data item** (binary length-prefixed CBOR only — zero JSON or text-delimited framing on `SLIPFORK_PROTOCOL_FD`; concrete message schemas locked in `M3.2.1`'s `docs/design/m3-test-orchestrator.md`).
   - **Framework-exposed DAG & persistent setup/fixture snapshots:** Testing frameworks will expose **nodes of the global DAG**, including **persistent setup/fixture stage nodes** (DB migrations, seed factories, S3 state) that **survive the setup process** because Slipfork freezes each materialized stage into a **read-only Btrfs subvolume snapshot** (`ADR-0010` §3), composing cleanly with global `[artifacts.*]` / `[fixtures.*]` DAG nodes.
   - **Protocol-native coverage & mutation testing (`mutants`):** Coverage and mutation testing (`mutants`) are **first-class concepts inside `STP v1` itself**, never hardcoded per-language Rust drivers inside Slipfork.
   - **Zero magic guessing & zero premature package publishing:** There is **no** "transparent" CLI-guessing adapter and **no** prematurely published plugin packages.
   - **Target-state language-blind Rust orchestrator + external ad-hoc proof plugins (`M3.2`):** In M3 Phase 2 (`M3.2`), `crates/slipfork-test` ships a **100% language-blind `STP v1` DAG orchestrator** (the RFC 8949 CBOR codec and 4-byte big-endian length framer are pure transport details over `SLIPFORK_PROTOCOL_FD`, never a per-language concern), proven in `M3.2` with external **ad-hoc, unpublished `pytest`, `vitest`, and `phpunit` plugins**. Detailed `STP v1` message schemas and the `M3.2` execution plan build directly on this framing contract in Phase 2.
4. **Speed & Stability Invariants (M3 target state `M3.13`–`M3.15` & `M3.2`):**
   1. **Pre-Warmed Btrfs World Slots (`M3.13`–`M3.15`, `M3.2`):** Background replenishment boots cloned Btrfs worlds (`postgres` + app servers + `test-<slot>.<project>.localhost` route, verified protocol-ready by `BtrfsEngine::spawn_service`'s `ReadinessProbe`, `ADR-0002` §2) ahead of demand.
   2. **Shared Host Browser + Per-Test `BrowserContext` over `http://test-<slot>.<project>.localhost` (`M3.2`):** One warm host browser creates isolated `< 5 ms` `BrowserContext`s against port-80 `slipforkd` routes.
   3. **O(1) Btrfs Subvolume Snapshots & Clones (`ArtifactStore` + `BtrfsEngine` over `SubvolumeDriver`, `M3.12`–`M3.13` & `M3.2`, `ADR-0010` §§2–3, §5):** Content-addressed `[artifacts.*]` volumes, persistent setup/fixture stage snapshots, and live `test-<slot>` worlds share the single injected `Arc<dyn SubvolumeDriver>` seam (`ADR-0010` §5).
   4. **Hermetic `CHECKPOINT` Before Freeze (`M3.13` & `M3.2`):** Every reusable PostgreSQL stage flushes `CHECKPOINT;` cleanly inside the running `postgres:<v>` container before `freeze_world` stops services and seals the read-only Btrfs subvolume (`ADR-0009` §2, `ADR-0010` §3) so clones never replay crash-recovery WAL.
5. **Typed `[test]` Schema (`0.1.0` `crates/slipfork-dag`) & Surviving `SLIPFORK_OUTPUT_DIR` Orthogonality (`M3.2`):**
   - **Typed `[test]` Intent — One Canonical Activation Rule (`Forkfile`, shipped in `0.1.0`):**
     ```toml
     [test]
     coverage = true
     coverage_report = ["html", "xml"]
     coverage_fail_under = 85        # optional (validated CoverageThreshold in 0..=100)
     ```
     `coverage = true` is the **sole switch** enabling coverage (`coverage_report` defaults to `["text"]` when omitted). Setting `coverage_report` or `coverage_fail_under` without `coverage = true` fails parse-time validation (`DagError::CoverageOptionsRequireEnabled`); an explicitly empty `coverage_report = []` fails parse-time validation (`DagError::EmptyCoverageReport`); duplicate report formats collapse into the typed set; and `coverage_fail_under` validates into `CoverageThreshold` (`0..=100`, `DagError::InvalidCoverageThreshold`). `[test]` parses into `TestSpec { pub coverage: Option<CoverageConfig> }` (`None` when disabled), to be enforced at runtime in `M3.2` by the language-blind `STP v1` orchestrator (`§3`) without per-language Rust coverage drivers.
   - **Blastit / Allure / Playwright Traces via Tool-Owned `SLIPFORK_OUTPUT_DIR` (target state `M3.2`):** In `M3.2`, Slipfork will mount a slot-scoped output directory read-write into each test world and runner as `SLIPFORK_OUTPUT_DIR` and preserve it across world teardown. External suites (Blastit `blastit dev -- ...` in `modes.local.components.<id>.run_command`, Playwright traces, Allure) write to `SLIPFORK_OUTPUT_DIR` through their own native tooling with zero shell-pipeline config in `Forkfile` and zero tool-specific collector traits inside Slipfork.

## Consequences

- Keeps `crates/slipfork-test` (`M3.2`) 100% language-blind over `STP v1` (`SLIPFORK_PROTOCOL_FD`), unifies persistent framework setup/fixture stages with Btrfs read-only subvolume snapshots (`ADR-0010`), elevates coverage and `mutants` into the protocol itself, and preserves shipped typed `[test]` thresholds and `M3.2` `SLIPFORK_OUTPUT_DIR` mounts with zero shell plumbing.
