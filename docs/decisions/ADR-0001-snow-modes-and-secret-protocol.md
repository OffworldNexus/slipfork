# ADR-0001: `Forkfile` `modes`, `!!` Write-Once Secret Generation, and Open Secret Provider Protocol (`OSPP v1`)

- **Status:** Partially Superseded in `0.1.0` — **§§1–2 (`Forkfile` `modes:`, `Faceless` `${{ ... !! ... }}`, and `Forkfile`) are superseded and deleted pre-`1.0` in favor of [`docs/design/forkfile.md`](../design/forkfile.md)** (`<repo_root>/Forkfile` in `crates/slipfork-forkfile`: Cargo-style `features`, procedural `on <expr>`, `postgres <cluster> { database <db> }` / `redis` / `s3` / `domain`, `secret(KEY) ?? random_hex(32)` write-once generation, `TaintedString` secret taint, and whole-file `line:col` static checking). **§3 (Two-Tier `SecretVault` / `FileVaultProvider` `0600` local vault vs strictly in-memory `OSPP v1` remote secrets in [`docs/design/ospp.md`](../design/ospp.md) and `ADR-0008`) remains active and normative** (with `subscribe.forkfile` carrying the active `EvaluatedFork` JSON).
- **Date:** 2026-11-15 (amended 2026-11-19)

## Context & Active Decision (§3 Two-Tier Secret Boundary)

1. **Single Procedural Manifest (`docs/design/forkfile.md`):** `<repo_root>/Forkfile` replaces both `Forkfile` and `Forkfile` pre-`1.0` with zero dual-syntax fallback branches. Optional top-level `project <slug>` overrides VCS-derived `ProjectSlug` locally while OSPP `subscribe` continues to identify repositories strictly by verbatim Git `remote`.
2. **Write-Once Local Secret Generation (`secret(<KEY>) ?? <generator>`):** In `Forkfile`, `secret(<KEY>) ?? <generator>` (`random_hex(N)`, `random_base64(N)`, `random_string(N)`, `uuid4()`) reads `<KEY>` from `SecretProvider`; when absent locally, generates a CSPRNG value and persists it atomically via `ensure_secret` (`put_if_absent`).
3. **Open Secret Provider Protocol (`OSPP v1`) & Two-Tier Secret Boundary (`docs/design/ospp.md`, `ADR-0008`, `ARCHITECTURE.md` §3.1 — ACTIVE):**
   - **CI holds remote authority; remote OSPP secrets never touch disk.** [`docs/design/ospp.md`](../design/ospp.md) is the sole normative OSPP v1 wire specification (`Sec-WebSocket-Protocol: ospp-v1` persistent JSON WebSocket, `p256` auth & ALTCHA+PoP `#handle=` pairing, verbatim Git `remote` identity, evaluated active `forkfile` JSON + uniform ID-only `claims`, per-subscription in-memory `hpke-p256` secret encryption, out-of-band `SetupBaseR` encrypted dumps, and live `env_updated` pushes). Local world `.localhost` origins always override cloud `domain` records, and OSPP is never a prerequisite for local worlds (`ADR-0005` §1).
   - **Two-tier secret boundary:** `FileVaultProvider` (`0600` `<data_home>/slipfork/vaults/<project>.json`, exposed to `DaemonService` solely through `crates/slipfork-edge`'s `trait SecretVault` and to `ForkFile` resolution through read/ensure `trait SecretProvider`) stores **strictly local** credentials and overrides — locally-provisioned backing-service passwords, `slipfork secret` overrides, and local `secret(...) ?? <generator>` secrets. `SecretVault::keys` plus locally-provisioned resources/domains automatically populate ID-only `subscribe.claims`, while unclaimed server-resolved values and `{ "encrypted": "<base64>" }` secrets / dump streams stay strictly in `slipforkd` memory.
