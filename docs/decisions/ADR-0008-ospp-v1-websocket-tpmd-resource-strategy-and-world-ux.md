# ADR-0008: `OSPP v1` WebSocket Protocol, `tpmd` P-256 Device Keys, Mode-Aware `ResourceStrategy`, Unprivileged `LISTEN_FDS` `slipforkd`, `<= 31`-Byte Service Labels, and World Rescue UX

- **Status:** Proposed — blocked on `H-010` (`direction-challenge`) (`H-003`, `H-008`, `H-009` validated; `H-006` closed by deferral; `H-004` open; supersedes `ADR-0001` §3's M1 REST sketch)
- **Date:** 2026-11-15

## Context

1. **M1's two-endpoint REST OSPP sketch cannot stream database dumps or reuse hardware-backed device keys:** Per owner directive, Slipfork defines the **Open Secret Provider Protocol (`OSPP v1`)** over WebSocket to deliver `vars`/`secrets`/`!!`, optional remote dev S3 coordinates, and streaming `zstd` PostgreSQL seed dumps authenticated by `tpmd` ECDSA P-256 keys (`docs/research/tunnel-weaver-and-systemd-facts.md` §2–§4) — while keeping `slipfork test` hermetic by default and offline laptops 100% functional on `~/.local/share/slipfork/vaults/<project>.json` (`0600`). Workspace version is `< 1.0.0`, so M1's REST sketch is deleted outright.
2. **Opaque hook failures, TTY traps, and manual port plumbing break human and AI-agent DX:** Truncating migration output, destroying failed worlds before inspection, omitting non-interactive `slipfork exec` / `--no-tty` paths for coding agents, or forcing manual `nsenter`/`socat` wrappers for `psql`, `redis-cli`, `pdb`, and host GUI clients violates Slipfork's DX-first mandate.
3. **Host facts constrain unprivileged port-80 activation and Tunnel Weaver labels:** On Linux (`ip_unprivileged_port_start = 1024`), unprivileged processes cannot `bind()` `:80`; PID 1 `systemd` must pass `LISTEN_FDS` sockets (starting at `fd 3` in **blocking** mode with `LISTEN_PID == getpid()`) to an unprivileged `slipforkd` (`facts.md` §5). Furthermore, `weaver-proto` caps service names at **`SERVICE_NAME_MAX = 31` bytes** (`15 + 1 + 15 + 1 + 31 = 63` RFC 1035 octets, charset `^[a-z0-9]+(-[a-z0-9]+)*$`, `facts.md` §1).

## Decision

1. **`OSPP v1` Ownership, Synchronous WebSocket Handshake, `DeviceKeySigner`, and Fragment Pairing (`crates/slipfork-ospp`, normative):**
   - **Protocol Ownership & Synchronous I/O Posture:** `OSPP v1` is **Slipfork's own open protocol specification**, authored and owned by this repository (to be verified by golden byte vectors and an in-tree reference server in `crates/slipfork-ospp/tests/critical_ospp.rs`, `M2.13`–`M2.14`). External control planes (such as Kerfufoo) are downstream implementers, never an assumed pre-existing contract. All Slipfork crates use **synchronous blocking I/O** (`std::net::TcpStream`, `UnixStream`, synchronous `tungstenite` over `rustls` + `webpki-roots`, `std::thread`; zero `tokio` or async runtime).
   - **Transport & Framing:** Dial `wss://<host>[:<port>]/_ospp/v1/connect` via `tungstenite` + `rustls` + `webpki-roots` (`ws://127.0.0.1:<port>/...` allowed strictly on loopback for local/test harnesses) with WebSocket subprotocol **`ospp-v1`**. Control/RPC messages are UTF-8 JSON text frames capped at **`16_384` bytes (16 KiB)** with a `10 s` first-message deadline (injected timeout/clock). Any client frame before `CHALLENGE` or capability frame before `WELCOME` fails closed.
   - **Device Key, `DeviceKeySigner` & Generic `FallbackDeviceKeySigner<P, F>`:** Keys use **ECDSA P-256 + SHA-256**. Validated `KeyId` **is** the 33-byte SEC1 compressed public key rendered **`p256:<66 lowercase hex>`**; `DeviceSignature` is raw fixed-width **`r || s` (64 bytes, never ASN.1 DER)**; `Debug` never prints private key bytes. `pub trait DeviceKeySigner: Send + Sync { fn key_id(&self) -> &KeyId; fn backend_label(&self) -> &'static str; fn sign(&self, message: &[u8]) -> Result<DeviceSignature, OsppError>; }` SHA-256 hashes `message` once internally before signing:
     - `TpmdDeviceKeySigner` probes `KeyStorePaths` (resolved at the Composition Root: **`$XDG_RUNTIME_DIR/tpmd/tpmd.sock`** when `XDG_RUNTIME_DIR` is set, then **`/run/tpmd/tpmd.sock`**; wire framing gated on `H-010` #3) in exact order, issuing atomic get-or-create (`ResumeOrCreate`) under app namespace `"slipfork"` with security floor **`sealed` (`allow_below_floor: false`)**, and verifies every returned signature against `key_id`.
     - Generic `FallbackDeviceKeySigner<P: DeviceKeySigner, F: DeviceKeySigner>` (wired at the Composition Root as `FallbackDeviceKeySigner<TpmdDeviceKeySigner, SoftwareP256Signer>`, where `SoftwareP256Signer` loads `SoftwareP256Key` from injected `DeviceKeyStore` using `0600` `flock` + `O_EXCL` + atomic rename and `EntropySource`) selects `F` **only** when `P` reports every `tpmd` candidate absent or backend-unavailable, emitting **one explicit diagnostic** naming the reason and security level (`software:file-0600, below tpmd sealed floor`). Locked stores wait (interruptible), while floor-policy mismatches, permission denial, malformed frames, or signature verification failures **fail closed** — never silently downgrading a sealed key to a file key.
   - **Server-Speaks-First Transcript (`CHALLENGE -> HELLO -> WELCOME | REJECT`):**
     1. Server sends `{"type":"challenge","nonce_s":"<64 lowercase hex>"}` (32 CSPRNG bytes, single-use per connection).
     2. Client generates 32 CSPRNG bytes `nonce_c` (via `EntropySource`) and sends `{"type":"hello","version":1,"key_id":"p256:<66 hex>","nonce_c":"<64 hex>","sig":"<128 hex>"}` (`version: u16 = 1` first), signing the exact bytes `"ospp-v1" || nonce_s(32) || nonce_c(32) || server_name` (`server_name` = exact dialed lowercase ASCII hostname without port on both ends).
     3. Server verifies key registration and `sig` over its `nonce_s` and replies `{"type":"welcome","version":1}` or `{"type":"reject","reason":{"kind":"unknown_key"|"bad_signature"|"unsupported_version", ...}}` (`UnsupportedVersion { min, max }`).
     4. **TLS Channel Binding Posture:** TLS exporter channel binding is **not** enabled in `ospp-v1` (matching `weaver-mux-v1`, `facts.md` §3; future channel binding would bump `version` to `2`).
   - **Browser-Fragment Pairing (`/_ospp/v1/pair`, `slipfork auth login [- | '<url>#handle=<64 hex>']`):** Single-use 32-byte pairing handles (5-minute server TTL) travel **exclusively** in the URI fragment (`#handle=<64 lowercase hex>`, never query/path). Reading the URL from `stdin` (`slipfork auth login -`) is the canonical agent/script form so handles never enter `argv`; `PairingUrl::parse` fails closed if `#handle=` is absent or malformed. On `/_ospp/v1/pair` (`ospp-v1`), after `CHALLENGE { nonce_s }`, the client sends `{"type":"pair_hello","version":1,"key_id":"p256:<66 hex>","nonce_c":"<64 hex>","handle":"<64 hex>","sig":"<128 hex>"}` signing `"ospp-v1-pair" || nonce_s(32) || nonce_c(32) || handle_bytes(32) || server_name`, zeroizes `handle` immediately, optionally invokes injected `BrowserOpener`, and receives `{"type":"pair_approved","account":"..."}` or `{"type":"reject","reason":{"kind":"unknown_handle"|"expired_handle"|"already_redeemed"|"bad_signature"|"unsupported_version"}}`. `#handle=[REDACTED]` is enforced across all logs, errors, and `--json` output, and CLI output prints the full `key_id` plus actual `backend_label()`.

2. **`OSPP v1` Post-`WELCOME` Capabilities & Engine-Agnostic Streaming Seed Dumps (`crates/slipfork-ospp`):**
   - Requests dispatch through **one typed capability enum** over a per-world-boot `OsppClient` instance (zero `OnceLock`/`static` globals):
     - **`EnvBundle` & `SecretsEnsure` (`SecretProvider`):** Fetches `vars`, `secrets`, and `domains` (`cloud` only) and executes `secrets.ensure` (`put_if_absent` CAS). `OsppSecretProvider` implements `SecretProvider` (`Send + Sync`, `&self`) over WebSocket with **zero filesystem writes**. In `local` mode, `LayeredSecretProvider` (`slipfork-snow`, sole owner of `0600` vault writes via `FileVaultProvider`) reads `FileVaultProvider` first then `OsppSecretProvider` (converging on any existing remote secret) and writes newly generated `!!` secrets exclusively to `FileVaultProvider` (`H-003`).
     - **`ResourcesDescribe` (`RemoteResourceBundle`):** Returns typed `s3_buckets.<id>.{endpoint, region, bucket, access_key, secret_key}` (redacted `Debug`) and `pg_databases.<id>` `PgDumpMetadata { db_id, sha256_compressed, compressed_bytes, format: PgCustomZstd }`.
     - **`DumpStream` & `SeedDumpStore`:** After `dump.begin`, the server streams binary WebSocket frames (`<= 64 KiB` hard cap; binary frames outside `dump.begin..dump.end` fail closed) carrying a `zstd`-compressed `pg_dump --format=custom` archive until `dump.end`. `DumpStreamer` streams through a bounded `zstd` window + incremental SHA-256 over the compressed stream into `SeedDumpStore::write_from(&self, sha256_compressed, &mut dyn Read)` (`DiskSeedDumpStore` wired at the Composition Root over XFS-verified `<cache_root>/dumps/<sha256>.part`, rejecting `/tmp` `tmpfs`). Any truncation or SHA-256 mismatch aborts and unlinks `.part` **before** any DB mutation. Verified `<sha256>.pgdump` files mount `MountMode::ReadOnly` into the `base` world via `WorldSpec.mounts` and restore via `WorldEngine::exec_in_world` (`pg_restore --no-owner --no-privileges --clean --if-exists`), followed by `CHECKPOINT;` and `WorldEngine::freeze_world` **before** `pre-deploy` migrations — requiring **zero `WorldEngine` downcasts**. Non-zero `pg_restore`/`CHECKPOINT` exit or a missing `pg_restore` binary inside the world **fails closed** via §4's rescue UX (never silently degrading to empty `initdb`).

3. **World-Scoped `[resources]` `ResourceStrategy` & Single `ResourcePlan::resolve` Owner (`crates/slipfork-dag`, `slipfork.toml`):**
   - `ResourceMode { Local, Test }` (`Serialize` only, never `Deserialize`) derives strictly from **`WorldTarget`** (`WorldTarget::TestSlot(_) => ResourceMode::Test`; `Canonical | UserFork(_) => ResourceMode::Local`; `cloud` is absent because cloud resources belong to the remote control plane's `EnvGroup`), guaranteeing M3's pre-warmed `TestSlot` pool is hermetically `Test` by construction.
   - `SlipforkConfig.resources: ResourcesSpec` parses `[resources.s3_buckets.<id>]` and `[resources.pg_databases.<id>]` tables with optional `local` and `test` keys set to `ResourceStrategy { Local, PreferRemote, Remote }` (`"local" | "prefer_remote" | "remote"`, `#[serde(deny_unknown_fields)]`, zero boolean mode flags; unknown keys, unknown modes, or empty tables fail closed at `parse_toml`, and the Composition Root cross-checks declared IDs against `SnowFile` via `ResourcesSpec::validate_declared_ids`).
   - **Single Resolution Owner (`ResourcePlan::resolve` in `crates/slipfork-dag`):** `ResourcePlan::resolve(spec: &ResourcesSpec, mode: ResourceMode, dump_policy: DumpPolicy, offer: Option<&RemoteResourceOffer>) -> Result<ResourcePlan, DagError>` is the **sole** decision point consumed by `slipfork up`/`fork`, `OsppClient`, and M3 `TestCoordinator` (never re-derived):
     - **`ResourcesSpec::defaults_for(ResourceMode::Local)` (`Canonical` / `UserFork`):** `ResourceStrategy::PreferRemote` — uses OSPP-offered shared dev S3 coordinates and dev DB seed dumps when paired and offered; when unpaired, offline, or omitted, uses world-local `ResourceCoordinates` (`127.0.0.1:9000` inside the world `netns`) / cached digest-pinned dump or clean `initdb` **while emitting one mandatory `[resources]` diagnostic line per resource** (and typed `--json` field) naming the effective strategy, resolved target (`remote` vs `local`), and reason. Per-invocation `--resources local` forces `ResourceStrategy::Local` for every resource without editing `slipfork.toml`.
     - **`ResourcesSpec::defaults_for(ResourceMode::Test)` (`TestSlot`):** `ResourceStrategy::Local` (**hermetic by default**) — always uses world-local `ResourceCoordinates` and clean `initdb -> migrate -> [fixtures.*]`, never mutating shared dev S3 or pulling dev dumps unless the resource's `test = "remote"` / `"prefer_remote"` key explicitly overrides it.
     - **Mutually Exclusive `--no-dump | --refresh-dump` (`DumpPolicy`):** CLI flags `--no-dump` (`DumpPolicy::NoDump`, skips dumps and uses clean `initdb` with diagnostic) and `--refresh-dump` (`DumpPolicy::RefreshDump`, requires live OSPP metadata check) are mutually exclusive; when neither is passed (`DumpPolicy::Default`), the effective `ResourceStrategy` decides. Both `ResourceStrategy::Remote` and `DumpPolicy::RefreshDump` **fail closed** when OSPP is unpaired, unreachable, or omits the resource (and `RefreshDump` combined with `ResourceStrategy::Local` fails closed as a configuration conflict).
   - **Origin Precedence:** Slipfork-assigned `WorldOrigin` (`Local | Shared`) always overrides provider `domains::` (`ADR-0005` §1).

4. **Mode-Scoped Components, Single Env Owner (`exec`), Inspectable Hook Rescue & `--world` CLI (`crates/slipfork`):**
   - **Mode-Scoped Components:** Supervised per `ADR-0001` §1's sole `SnowFile::effective_components(mode)` contract.
   - **Uniform `--world <fork>` Selector & Readiness:** Every world-scoped command selects non-default worlds exclusively via `--world <fork>` (zero positional `[<fork>]` aliases on `up`, `down`, `shell`, `logs`, `hook run`, `db`, `redis`, `forward`, `share`, `exec`; omitting `--world` resolves `cwd` by nearest ancestor: `.worktrees/<fork>[/...]` -> `UserFork(<fork>)`, repo root -> `Canonical`). `slipfork up` / `fork` streams hooks (`<component>:<phase>`, e.g. `api:pre-deploy`) via `WorldEngine::exec_in_world(..., on_output)`, waits for declared component `internal_ports` readiness before printing `[origin]`, and is idempotent when already running. On non-zero hook exit, Slipfork prints hook ID, exact `argv`, exit code, world ID, log path, and **full un-truncated output** (spilling to disk above a bounded RAM window), **preserves the failed world**, and prints three rescue commands (`slipfork hook run <hook_id> --world <fork>`, `slipfork logs --world <fork> <hook_id>`, `slipfork shell --world <fork>`, noting `--no-tty` and `slipfork exec` when `!isatty`). Canonical `slipfork list --json` and `up --json` schemas live in `docs/design/target-dx.md` §1.5.
   - **Single Env Owner (`slipfork exec`) & Interactive PTY:** `slipfork exec [--world <fork>] [--cwd <cwd>] -- <argv>...` is the **sole owner** of in-world `snow.yml` (`modes.local`) environment resolution and injection (`@slipfork/opencode` only routes commands via `ctx.shell.hook` and never injects env vars, `ADR-0004`). `WorldEngine::exec_interactive_in_world` takes an explicit `InteractiveTty` handle constructed at the Composition Root (single-shot `SIGWINCH` forwarding + RAII `termios` restore; failing closed without a TTY and naming `--no-tty` / `slipfork exec`) to power `slipfork hook run` (`--no-tty` uses `exec_in_world`), `slipfork shell`, `slipfork db` (`psql`), and `slipfork redis` (`redis-cli`; missing binaries or ambiguous targets fail closed). `WorldEngine` retains bounded logs across `stop_service` for `slipfork logs [--world <fork>] [<target>] [--follow] [--stderr] [--lines <n>]`. `slipfork forward [--world <fork>] [--json] [<target>...]` binds host `127.0.0.1:0`, bridges TCP via `WorldEngine::dial_world_tcp` (logging per-connection errors without crashing), and flushes URIs immediately. `slipfork secret set [--force] <KEY>` / `unset <KEY>` / `list` manage `0600` vault keys without echoing values.

5. **Unprivileged `LISTEN_FDS` `slipforkd` & Systemd Unit Generator (`crates/slipfork-edge`):**
   - **`slipfork daemon unit` (`UnitSpec`):** Purely renders `slipforkd.socket` (emitting listeners in fixed order: `ListenStream=127.0.0.1:80`, `ListenStream=[::1]:80`, `ListenStream=127.0.0.1:<forward_port>`, `NoDelay=true`, `Service=slipforkd.service`) and `slipforkd.service` (`Type=simple`, `User=<user>`, empty `CapabilityBoundingSet=`, `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ReadWritePaths=<state_dir> <runtime_dir>`, `PrivateTmp=yes`, `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX`), supporting `--only socket|service` and `--forward-port <u16>` and failing closed on empty `listen_addrs` (`EdgeError::UnitNoListener`) or port collision (`EdgeError::UnitPortCollision`).
   - **Explicit FD-Order Non-Blocking Activation (`adopt_systemd_listener`):** Using `#![forbid(unsafe_code)]` via `listenfd`, when `LISTEN_PID` or `LISTEN_FDS` is present in `activation.rs`, `slipforkd` verifies `LISTEN_PID == getpid()`, calls **`set_nonblocking(true)` immediately** on every inherited socket (`fd >= 3`), and assigns roles deterministically without inspecting port numbers:
     - **`LISTEN_FDS == 1`:** `fd 3` is the sole HTTP ingress (`forward_listener = None`; `share_world` fails closed naming the missing forward listener), enabling unprivileged `systemd-socket-activate -l 127.0.0.1:0` directly.
     - **`LISTEN_FDS >= 2` (matching `UnitSpec`'s emitted order):** leading descriptors (`127.0.0.1:80`, `[::1]:80`) become `http_listeners` and the trailing descriptor (`127.0.0.1:<forward_port>`) becomes `Some(forward_listener)`.
     - **Any other count/shape or broken fd** fails closed (`EdgeError::ActivationBroken`, or `EdgeError::ActivationMismatch` on `LISTEN_PID != getpid()`) — **never** self-binding or retrying `--listen`. Only when both activation env vars are absent does `slipforkd` bind `--listen <addr>` (`--forward-port <u16>`); when neither is provided, it fails closed (`EdgeError::NoListener`). HTTP/1.1 request headers are parsed via `httparse` under a `<= 16 KiB` policy cap and bounded read timeout.

6. **Deterministic `<= 31`-Byte Tunnel Weaver Service Labels (`crates/slipfork-world`, normative):**
   - `WeaverServiceName` enforces `weaver-proto`'s **`SERVICE_NAME_MAX = 31`** bytes and charset `^[a-z0-9]+(-[a-z0-9]+)*$`.
   - `derive_weaver_service_name(full_label)` validates/normalizes `<project>` / `<project>-<fork>` to lowercase single-dash `[a-z0-9]` runs (failing closed if empty or invalid): if `normalized.len() <= 31` **and** it neither equals `[0-9a-f]{12}` nor ends with `-[0-9a-f]{12}`, it returns `normalized` verbatim; otherwise it computes `hash12 = hex(sha256(normalized))[..12]`, takes `prefix = normalized[..min(normalized.len(), 18)].trim_end_matches('-')` (`31 - 1 - 12 = 18`), and emits `<prefix>-<hash12>` (or `<hash12>` if `prefix` is empty), keeping verbatim and hashed codomains strictly disjoint and `<= 31` bytes.

7. **Crate Boundaries, Workspace Dependencies, `unsafe` Policy & External Gates:**
   - **Workspace Crates & Dependencies (`M2.2`):** Adds `#![forbid(unsafe_code)]` crates `crates/slipfork-ospp` (zero `std::env`, zero `slipfork-engine` dep), `crates/slipfork-edge` (`std::env` confined to `activation.rs`, safe `listenfd` socket adoption, `httparse` with `<= 16 KiB` header cap), and `crates/slipfork-vcs` (`RepoRootResolver` + `VcsWorkspace` + `remote_helper`, zero `src/bin/*`), with minimal workspace dependencies `tungstenite`, `rustls`, `webpki-roots`, `p256`, `zstd`, `listenfd`, `socket2`, and `httparse` (plus `tpmd` framing dep per `H-010` #3). `M2.4` deletes `OsppBundle` and `MemorySecretProvider::from_bundle` from `crates/slipfork-snow`; `M2.5` gates `FsMerkleHasher`/`FsDigestCache` behind `#[cfg(feature = "fs")]` (`default = []`) in `crates/slipfork-dag`; `crates/slipfork-engine` (depending on `slipfork-world`, never `slipfork-snow`; `EngineCapabilities` deleted in `M2.6`) confines `unsafe` strictly to `linux_cow.rs` and `pty.rs` with per-call `// SAFETY:` proofs; and `crates/slipfork` (`slipfork`, `slipforkd`, `git-remote-slipfork`) is the sole Rust Composition Root (`HOME` unset fails closed before any side effect).
   - **External Gates:** Per closed `H-006` (`plan/HUMAN.md`), `weaved`'s wire adapter stays isolated in `M2.22` until `tunnel-weaver` publishes its IPC spec; until then, `UnavailableTunnelRegistrar` makes `slipfork share [--world <fork>]` **fail closed** (`EdgeError::TunnelUnavailable`, deleted once `WeavedRegistrar` lands in `M2.22`), while `slipfork share --stop [--world <fork>]` (`unshare_world`) on an unshared world is an idempotent success no-op returning `WorldOrigin::Local`. Live `IncusEngine` integration stays isolated in `M2.21` behind open `H-004`.

## Consequences

- Proposes one synchronous, non-leaky M2/M3 DI tree across Slipfork-owned `OSPP v1` WebSocket auth/dumps, `ResourcePlan::resolve` target-scoped hermeticity, unprivileged `LISTEN_FDS` `slipforkd`, collision-free `<= 31`-byte service labels, and uniform `--world` PTY + AI-agent tooling, pending owner ruling on `H-010`.
