# ADR-0008: `OSPP v1` Live Subscriptions & HPKE Secrets, Two-Tier `SecretVault` Boundary, Mode-Aware `ResourceStrategy`, Unified Unprivileged `slipforkd` (`LISTEN_FDS`), `<= 31`-Byte Service Labels, and World Rescue UX

> Normative wire specification: [`docs/design/ospp.md`](../design/ospp.md). User-facing documentation: [OSPP v1](../reference/ospp.md).

- **Status:** Accepted — amended in `0.1.0` (`M3.29` target state) to align with [`docs/design/ospp.md`](../design/ospp.md) (all-JSON `ospp-v1` wire, `hpke-p256` in-memory remote secrets, daemon-owned out-of-band encrypted dumps, and the two-tier `SecretVault` local `0600` boundary), `ADR-0009` (`crun` service containers), `ADR-0010` (`BtrfsEngine`), `ADR-0011` (`daemon install` & `<state_dir>/run`), and `M3.28.20` (`AF_NETLINK`)
- **Date:** 2026-11-15

## Context

1. **CI holds cloud authority while local worlds need both zero-disk remote secrets and persistent local service credentials:** Slipfork is a local "cloud in a box" paired with CI (Kerfufoo or compatible providers) over the **Open Secret Provider Protocol (`OSPP v1`)**. Server-resolved cloud secrets and database dumps must never be written to local disk, yet locally-provisioned backing-service credentials (local PostgreSQL/Redis passwords reconnecting to persistent Btrfs world state across daemon/host restarts), `slipfork secret` overrides, and local-mode `!!` secrets must persist locally on offline laptops while keeping `slipfork test` hermetic by default.
2. **Splitting world ownership across CLI and daemon forces leaky cross-process handles or `SCM_RIGHTS` PTY hacks (`H-010`):** Because `slipforkd` runs unprivileged as `User=<developer-user>` (resolved once at the CLI composition boundary via `UserIdentity`), making `slipforkd` the **single local Composition Root and authority** while keeping `slipfork` a thin control-socket client that enters worlds directly inheriting its native terminal (`stdin`/`stdout`/`stderr`) eliminates cross-process `WorldHandle` lookup, `SCM_RIGHTS` FD passing, and custom PTY `unsafe` code simultaneously.
3. **Host facts constrain unprivileged port-80 activation, ephemeral ports, and Tunnel Weaver labels:** On Linux (`ip_unprivileged_port_start = 1024`), unprivileged processes cannot `bind()` `:80`; PID 1 `systemd` hands `LISTEN_FDS` sockets (starting at `fd 3` in **blocking** mode with `LISTEN_PID == getpid()`) to `slipforkd` (`docs/research/tunnel-weaver-and-systemd-facts.md` §5), while zero-setup unprivileged runs use `--listen 127.0.0.1:0` requiring port-qualified `WorldOrigin::local` URLs (`H-010` #2, `ADR-0011`). Furthermore, `weaver-proto` caps service names at **`SERVICE_NAME_MAX = 31` bytes** (`15 + 1 + 15 + 1 + 31 = 63` RFC 1035 octets, charset `^[a-z0-9]+(-[a-z0-9]+)*$`, `facts.md` §1).

## Decision

1. **`OSPP v1` Ownership, Single `OsppEndpoint`, Synchronous `p256` Handshake & ALTCHA + PoP Pairing (`crates/slipfork-ospp`, `M3.29` target state, `docs/design/ospp.md`):**
   - **Single Normative Wire Source, Single `OsppEndpoint` & Synchronous Ports:** **`docs/design/ospp.md` is the sole normative OSPP v1 wire specification** (`Sec-WebSocket-Protocol: ospp-v1`, 100% UTF-8 JSON text frames discriminated by `"type"`, zero binary WebSocket frames, zero `#[serde(flatten)]` / `extra` catch-alls); this ADR does not duplicate a second frame table. One `OsppEndpoint` is injected at `slipforkd` boot across `connect`, `subscribe`, and `dump`, and `DaemonControl::auth_pair` **refuses** any CLI-supplied `<URL>` that differs from it. Every domain trait uses synchronous blocking signatures behind `trait OsppClient` + `trait OsppSession` (`pair`, `connect` -> `subscribe`, `dump`, `unsubscribe`, `close`).
   - **Machine Auth Key (`p256`) & Pairing (`slipfork auth <URL>`):** `DeviceKeySigner` (`SoftwareP256Signer` over `FileDeviceKeyStore` writing only the `0600` machine-auth P-256 scalar at the injected `DeviceKeyPath`, zeroizing `SoftwareP256Key` on `Drop`) signs `b"ospp-v1" || server_nonce || client_nonce` on `hello -> auth_challenge -> auth_response -> auth_ok` and `b"ospp-v1-pair" || server_nonce || client_nonce` alongside `hostname` + ALTCHA proof-of-work on `pair_hello -> pair_challenge -> pair_begin -> pair_handle -> pair_approved`. The client appends `#handle=<handle>` strictly as a URL fragment to the server-supplied `pair_handle.url` (never computing the URL from hostname), prints it and opens it via `BrowserOpener`, and awaits pushed `pair_approved { account, machine }` on that open WebSocket (socket-bound in server memory, one pending pairing per public key; disconnect or Ctrl-C cancels immediately).

2. **Two-Tier `SecretVault` Model, Automatic ID-Only `claims`, Live `hpke-p256` Subscriptions & Daemon-Owned Streaming Dumps (`ARCHITECTURE.md` §§3.1–3.3, `docs/design/ospp.md`):**
   - **Two-Tier Secret Boundary (`trait SecretVault` vs In-Memory OSPP):** **Tier 1 (`trait SecretVault` in `crates/slipfork-edge`: `get`/`put`/`remove`/`keys`, wired solely at `slipforkd`'s Composition Root over `FileVaultProvider` `0600` `<data_home>/slipfork/vaults/<project>.json`, with `trait SecretProvider` as the narrow read/ensure input to `SnowFile` evaluation)** stores **strictly local** credentials and overrides — locally-provisioned backing-service passwords (surviving restarts to reconnect to persistent Btrfs world state), `slipfork secret` overrides, and local-mode `!!` secrets. **Tier 2 (`OsppSession`, strictly in `slipforkd` memory)** holds all remote server-resolved secrets and dump streams, which **never touch `FileVaultProvider` or any file on disk**.
   - **Verbatim Git `remote`, `SecretVault::keys -> claims`, Unclaimed Plaintext Guarantee & `update_service_env`:** `subscribe` identifies the project solely by its **verbatim Git `remote` string** (local `ProjectSlug` never crosses the wire) and carries a fresh per-subscription **in-memory** ephemeral `hpke-p256` public key (`S=` zeroized on `unsubscribe`/`close`/`Drop`). `SecretVault::keys(project)` plus locally-provisioned `resources`, `domains`, and `components` automatically feed ID-only `claims` (never values). Unclaimed entries are resolved by the server to **guaranteed template-free plaintext** (sealing secret-contaminated outputs with RFC 9180 HPKE Base, `info = "ospp-v1-secret"`, `aad = "<component>:<env_key>"`) or refused with `error`; claimed entries retain `${{ ... }}` and are substituted locally solely through `SecretProvider` (`SecretVault`) + local `ResourceCoordinates` without re-scanning unclaimed outputs. On `env_updated`, `slipforkd` updates affected services via `WorldEngine::update_service_env(&ServiceHandle, &ExecEnv)` and restarts through `M3.28.17`'s shared boot pipeline, re-subscribing with the same `id` on config/vault change and sending `unsubscribe` on stop.
   - **Daemon-Owned Out-of-Band Encrypted Dump Restore (`SetupBaseR`):** `slipforkd` owns dump restore (`WorldEngine` carries no remote stream variant and sees only a sealed base snapshot). `OsppSession::dump` (`dump_request -> dump_ready -> HTTPS GET`) opens the server's `SetupBaseS(public_key, info = "ospp-v1-dump")` stream on the client with stateful `SetupBaseR` (`65`-byte `enc` + `4-byte BE len || ctx.Open(aad = "<subscription_id>:<resource>", ciphertext)` frames + `len = 0` EOF) while piping directly through bounded `zstd -d | pg_restore` (`--no-owner --no-privileges --clean --if-exists`) inside the transient seed world's `postgres:<v>` `crun` container (`ADR-0009` §2), followed by `CHECKPOINT;` and `WorldEngine::freeze_world` — writing **zero plaintext dump bytes to disk** and failing closed on truncation.
   - *(Superseded M2 drafts deleted pre-`1.0` in `M3.29`: M2's server-speaks-first challenge handshake, `server_name` suffix, `tpmd` / private-`tokio` signer, request/response bundle & resource-offer RPCs, `LayeredSecretProvider`, `OsppSecretProvider`, binary WebSocket dump frames, and `DiskSeedDumpStore` on-disk dump files were replaced cleanly by `docs/design/ospp.md`.)*

3. **World-Scoped `[resources]` `ResourceStrategy`, Offerless `ResourcePlan::resolve`, Port-Aware `WorldOrigin::local` & In-Netns Bridge (`H-010` #2, `H-011` #4):**
   - `ResourceMode { Local, Test }` derives strictly from `WorldTarget` (`TestSlot(_) => Test`, `Canonical | UserFork(_) => Local`), and `SlipforkConfig.resources: ResourcesSpec` parses `[resources.s3_buckets.<id>]` / `[resources.pg_databases.<id>]` overrides (`ResourceStrategy { Local, PreferRemote, Remote }`, `#[serde(deny_unknown_fields)]`).
   - **"Remote resource offer" is not a concept in OSPP v1:** remote coordinates arrive as `env_resolved`/`env_updated` env values and dumps use explicit `dump_request`/`dump_ready`. `slipfork_dag::ResourcePlan::resolve(spec, mode, dump_policy, ospp_paired)` is the **sole** resolution owner from `Forkfile` + `claims`/pairing state + local coordinates (`Local` defaults to `PreferRemote`, falling back to world-local SeaweedFS `127.0.0.1:9000` / clean `initdb` with typed `{strategy, resolved, reason}` diagnostics when unpaired; `Test` defaults to **hermetic `Local`**; `--no-dump | --refresh-dump` fail closed on unpaired `Remote`/`RefreshDump` or `RefreshDump + Local` conflicts).
   - `WorldOrigin::local(&LocalHostRoute, ingress_port)` omits `:80` and formats `:<port>` otherwise (overriding cloud `domains::`, `ADR-0005` §1; single untagged `struct WorldOrigin(LocalOrigin)` in `0.1.0`, `ADR-0011`), while `slipfork-world-init` binds `127.0.0.1:<local_ingress_port>` inside each world's netns and splices streams to `<state_dir>/http-ingress.sock` (`0600`).

4. **Thin-Client `slipfork` CLI, `<state_dir>/run`, Direct TTY Entry & Daemon-Owned `forward` (`H-010` #1, `ADR-0011`):**
   - `slipforkd` takes explicit `--state-dir <path> --runtime-dir <path>` (`Layout::for_account` defaults `runtime_dir` unconditionally to `<state_dir>/run`, `ADR-0011` §2) and binds `<runtime_dir>/daemon.sock` (`0600`). Only `up` and `fork` auto-spawn `slipforkd --listen 127.0.0.1:0`; every `cwd`-sensitive `DaemonControl` request carries explicit `cwd: PathBuf`.
   - Existing-world selection (`--world <world>` and `drop`) resolves `<project>`, `<project>:<fork>`, or `<fork>` via `resolve_world_selector` (`ADR-0005` §3); failed hooks stream full untruncated output, preserve the failed world, and print copy-pasteable rescue commands (`hook run`, `restart`, `logs`, `shell`).
   - `DaemonControl::exec_target` returns `WorldExecTarget` (`nsenter` into `slipfork-world-init` PID 1 for world entry or `crun exec` via `service_entry_command` for `db`/`redis`, `ADR-0009` §3) over `0600` `daemon.sock` so `slipfork` spawns children with `env_clear()` + `ExecEnv` and `Stdio::inherit()` (zero CLI<->daemon `SCM_RIGHTS`, zero `pty.rs` `unsafe`), while `DaemonControl::forward` binds host `127.0.0.1:0` bridges to `dial_world_tcp` for the control connection's lifetime.

5. **Unprivileged `LISTEN_FDS` `slipforkd`, `--listen` Mode, `ingresses` Routing & Non-Template Unit Generator (`H-010` #1, `ADR-0011` §1, `M3.28.20`):**
   - **Non-Template `slipfork daemon unit` & `daemon install` (`UnitSpec`):** Renders non-template `slipforkd.socket` (`ListenStream=127.0.0.1:80`, `[::1]:80`, `127.0.0.1:<forward_port>`, `NoDelay=true`, `Service=slipforkd.service`, `WantedBy=sockets.target`), `slipforkd.service` (`Type=simple`, explicit `User=<developer-user>`, `Requires=slipforkd.socket`, `After=slipforkd.socket`, `ExecStart=<executable> --state-dir <state_dir> --runtime-dir <runtime_dir>`, empty `CapabilityBoundingSet=`, `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ReadWritePaths=<state_dir> <runtime_dir>`, `PrivateTmp=yes`, **`RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX AF_NETLINK`** — `AF_NETLINK` is required because `slipfork-world-init` brings up the in-netns loopback interface via `ip link set lo up`, which fails with `EAFNOSUPPORT` inside the installed unit without it [`M3.28.20`], `WantedBy=multi-user.target`), and the 4-line `/etc/apparmor.d/slipfork` `userns` profile (`ADR-0010` §7, `ADR-0011` §1).
   - **Explicit FD-Order Activation & `--listen` (`adopt_systemd_listener`):** Verifies `LISTEN_PID == getpid()`, sets `nonblocking(true)`, maps `LISTEN_FDS == 1` to HTTP-only and `LISTEN_FDS >= 2` to `http_listeners` + trailing `forward_listener` (failing closed `ActivationBroken`/`ActivationMismatch` otherwise), and binds `--listen <addr>` (plus optional `--forward-port`) only when activation env vars are absent, routing `.localhost` requests (`httparse` `<= 16 KiB`) through `Forkfile` `ingresses`.

6. **Deterministic `<= 31`-Byte Tunnel Weaver Service Labels (`crates/slipfork-world`, normative):**
   - `WeaverServiceName` enforces `SERVICE_NAME_MAX = 31` bytes (`^[a-z0-9]+(-[a-z0-9]+)*$`): `derive_weaver_service_name` returns normalized labels `<= 31` bytes not matching `(^|-)[0-9a-f]{12}$` verbatim, and hashes longer/colliding labels to `<prefix_le_18>-<sha256_hex12>` so verbatim and hashed codomains are strictly disjoint.

7. **Crate Boundaries, Unified Daemon Composition Root & `M3.29.2` Target-State Dependencies (`H-010`, `H-011`):**
   - `slipforkd` is the single stateful Rust Composition Root assembling `BtrfsEngine` (`KernelBtrfsDriver`, `ADR-0010`), `FileVaultProvider` wired behind `trait SecretVault` (local credentials/overrides only), `WsOsppClient` / live `OsppSession` (`M3.29.2` target state in `crates/slipfork-ospp` over sync `tungstenite`, `rustls`, `webpki-roots`, `p256`, `hpke = "0.15.1"` [`alloc`, `nistp`, `aes`, `hkdfsha2`], `base64`, `zstd` — removing `tokio` and `tpmd-*`; zero OSPP secret writes, `FileDeviceKeyStore` writes only the `0600` machine key at `DeviceKeyPath`), `ResourcePlan`, `VcsWorkspaceFactory` + `RepoRootResolver`, and `WorldRegistry` in-process; `crates/slipfork-engine` confines `unsafe` strictly to `src/{btrfs.rs,linux_cow.rs}`, and `WeavedRegistrar` remains isolated in `M4.1` (`H-006`, `ADR-0011`).

## Consequences

- Locks one synchronous, non-leaky `0.1.0` DI tree inside unprivileged `slipforkd` with capability-honest `SecretVault`, one boot-injected `OsppEndpoint`, strictly in-memory `hpke-p256` remote secrets and `SetupBaseR` streaming dumps, `WorldEngine::update_service_env` live restarts, `AF_NETLINK`-capable systemd sandboxing, and collision-free `<= 31`-byte service labels.
