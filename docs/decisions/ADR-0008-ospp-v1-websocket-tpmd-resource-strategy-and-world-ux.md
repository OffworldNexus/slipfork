# ADR-0008: `OSPP v1` WebSocket Protocol, `tpmd` P-256 Device Keys, Mode-Aware `ResourceStrategy`, Unified Unprivileged `slipforkd` (`LISTEN_FDS`), `<= 31`-Byte Service Labels, and World Rescue UX

- **Status:** Accepted (`H-003`, `H-008`, `H-009`, `H-010`, `H-011` ratified; `H-006` closed by deferral; `H-004` open; supersedes `ADR-0001` §3's M1 REST sketch; amended by `ADR-0009` — seed restore and `psql`/`redis-cli` execute inside the `crun` service container, never the `L0` app rootfs)
- **Date:** 2026-11-15

## Context

1. **M1's two-endpoint REST OSPP sketch cannot stream database dumps or reuse hardware-backed device keys:** Per owner directive, Slipfork defines the **Open Secret Provider Protocol (`OSPP v1`)** over WebSocket to deliver `vars`/`secrets`/`!!`, optional remote dev S3 coordinates, and streaming `zstd` PostgreSQL seed dumps authenticated by `tpmd` ECDSA P-256 keys (`docs/research/tunnel-weaver-and-systemd-facts.md` §2–§4) — while keeping `slipfork test` hermetic by default and offline laptops 100% functional on `~/.local/share/slipfork/vaults/<project>.json` (`0600`). Workspace version is `< 1.0.0`, so M1's REST sketch is deleted outright.
2. **Splitting world ownership across CLI and daemon forces leaky cross-process handles or `SCM_RIGHTS` PTY hacks (`H-010`):** Because `slipforkd` runs unprivileged as `User=<developer-user>` (`H-010`'s `%i` shorthand denotes the developer's own OS account, resolved once at the CLI composition boundary via `UserIdentity` / `getpwuid_r(geteuid())`), making `slipforkd` the **single local Composition Root and authority** while keeping `slipfork` a thin control-socket client that enters worlds directly inheriting its native terminal (`stdin`/`stdout`/`stderr`) eliminates cross-process `WorldHandle` lookup, `SCM_RIGHTS` FD passing, and custom PTY `unsafe` code simultaneously.
3. **Host facts constrain unprivileged port-80 activation, ephemeral ports, and Tunnel Weaver labels:** On Linux (`ip_unprivileged_port_start = 1024`), unprivileged processes cannot `bind()` `:80`; PID 1 `systemd` hands `LISTEN_FDS` sockets (starting at `fd 3` in **blocking** mode with `LISTEN_PID == getpid()`) to `slipforkd` (`facts.md` §5), while zero-setup unprivileged runs use `--listen 127.0.0.1:0` requiring port-qualified `WorldOrigin::Local` URLs (`H-010` #2). Furthermore, `weaver-proto` caps service names at **`SERVICE_NAME_MAX = 31` bytes** (`15 + 1 + 15 + 1 + 31 = 63` RFC 1035 octets, charset `^[a-z0-9]+(-[a-z0-9]+)*$`, `facts.md` §1).

## Decision

1. **`OSPP v1` Ownership, Synchronous WebSocket Handshake, Pinned `tpmd` Crates & Fragment Pairing (`crates/slipfork-ospp`, normative):**
   - **Protocol Ownership & Synchronous Domain Ports:** `OSPP v1` is **Slipfork's own open protocol specification**, authored and owned by this repository (to be verified by golden WebSocket frame vectors and an in-tree reference server in `crates/slipfork-ospp/tests/critical_ospp.rs`, `M2.13`–`M2.14`; Kerfufoo and compatible vaults are downstream implementers). Every Slipfork domain trait uses **synchronous blocking signatures** (`std::net::TcpStream`, `UnixStream`, synchronous `tungstenite` over `rustls` + `webpki-roots`, `std::thread`).
   - **Transport & Framing:** Dial `wss://<host>[:<port>]/_ospp/v1/connect` via `tungstenite` + `rustls` + `webpki-roots` (`ws://127.0.0.1:<port>/...` allowed strictly on loopback for local/test harnesses) with WebSocket subprotocol **`ospp-v1`**. Control/RPC messages are UTF-8 JSON text frames capped at **`16_384` bytes (16 KiB)** with a `10 s` first-message deadline (injected timeout/clock). Any client frame before `CHALLENGE` or capability frame before `WELCOME` fails closed.
   - **Device Key, Pinned `tpmd` Git Crates (`H-010` #3) & Generic `FallbackDeviceKeySigner<P, F>`:** Keys use **ECDSA P-256 + SHA-256**. Validated `KeyId` **is** the 33-byte SEC1 compressed public key rendered **`p256:<66 lowercase hex>`**; `DeviceSignature` is raw fixed-width **`r || s` (64 bytes, never ASN.1 DER)**; `Debug` never prints private key bytes. `pub trait DeviceKeySigner: Send + Sync { fn key_id(&self) -> &KeyId; fn backend_label(&self) -> &'static str; fn sign(&self, message: &[u8]) -> Result<DeviceSignature, OsppError>; }` SHA-256 hashes `message` once internally before signing:
     - **Pinned Upstream `tpmd` Crates (zero hand-rolled IPC framing, `H-010` #3):** Matching `tunnel-weaver` (`crates/weave/Cargo.toml:53-55`), `crates/slipfork-ospp` depends directly on pinned `tpmd-client = { git = "https://github.com/OffworldNexus/tpmd", rev = "90cb2db45b3ea6bc065918f11c7e0fd23b4ce837" }` and `tpmd-ipc = { git = "https://github.com/OffworldNexus/tpmd", rev = "90cb2db45b3ea6bc065918f11c7e0fd23b4ce837" }` (`tpmd-proto` owns the framing). `TpmdDeviceKeySigner` encapsulates a private, instance-scoped `current_thread` `tokio::runtime::Runtime` (zero global runtime, zero async trait leak) to probe injected `KeyStorePaths` (**`$XDG_RUNTIME_DIR/tpmd/tpmd.sock`** when `XDG_RUNTIME_DIR` is set at the Composition Root, then **`/run/tpmd/tpmd.sock`**) in exact order, issuing atomic `ResumeOrCreate` under app namespace `"slipfork"` with security floor **`sealed` (`allow_below_floor: false`)**, and verifying every returned signature against `key_id`.
     - Generic `FallbackDeviceKeySigner<P: DeviceKeySigner, F: DeviceKeySigner>` (wired in `slipforkd` as `FallbackDeviceKeySigner<TpmdDeviceKeySigner, SoftwareP256Signer>`, where `SoftwareP256Signer` loads `SoftwareP256Key` from injected `DeviceKeyStore` using `0600` `flock` + `O_EXCL` + atomic rename and `EntropySource`) selects `F` **only** when `P` reports `tpmd` absent or unavailable across all candidates, emitting **one explicit diagnostic** naming the reason and security level (`software:file-0600, below tpmd sealed floor`). Locked stores wait (interruptible), while floor-policy mismatches, permission denial, protocol errors, or signature verification failures **fail closed**.
   - **Server-Speaks-First Transcript (`CHALLENGE -> HELLO -> WELCOME | REJECT`):**
     1. Server sends `{"type":"challenge","nonce_s":"<64 lowercase hex>"}` (32 CSPRNG bytes, single-use per connection).
     2. Client generates 32 CSPRNG bytes `nonce_c` (via `EntropySource`) and sends `{"type":"hello","version":1,"key_id":"p256:<66 hex>","nonce_c":"<64 hex>","sig":"<128 hex>"}` (`version: u16 = 1` first), signing `"ospp-v1" || nonce_s(32) || nonce_c(32) || server_name` (`server_name` = exact dialed lowercase ASCII hostname without port on both ends).
     3. Server verifies key registration and `sig` over its `nonce_s` and replies `{"type":"welcome","version":1}` or `{"type":"reject","reason":{"kind":"unknown_key"|"bad_signature"|"unsupported_version", ...}}` (`UnsupportedVersion { min, max }`).
     4. **TLS Channel Binding Posture:** TLS exporter channel binding is **not** enabled in `ospp-v1` (matching `weaver-mux-v1`, `facts.md` §3; future channel binding would bump `version` to `2`).
   - **Browser-Fragment Pairing (`/_ospp/v1/pair`, `slipfork auth login [- | '<url>#handle=<64 hex>']`):** Single-use 32-byte pairing handles (5-minute server TTL) travel **exclusively** in the URI fragment (`#handle=<64 lowercase hex>`, never query/path). Reading the URL from `stdin` (`slipfork auth login -`) is the canonical agent/script form so handles never enter `argv`; `PairingUrl::parse` fails closed if `#handle=` is absent or malformed. On `/_ospp/v1/pair` (`ospp-v1`), after `CHALLENGE { nonce_s }`, `slipforkd` sends `{"type":"pair_hello","version":1,"key_id":"p256:<66 hex>","nonce_c":"<64 hex>","handle":"<64 hex>","sig":"<128 hex>"}` signing `"ospp-v1-pair" || nonce_s(32) || nonce_c(32) || handle_bytes(32) || server_name`, zeroizes `handle` immediately, and receives `{"type":"pair_approved","account":"..."}` or `{"type":"reject","reason":{"kind":"unknown_handle"|"expired_handle"|"already_redeemed"|"bad_signature"|"unsupported_version"}}`. `#handle=[REDACTED]` is enforced across all logs, errors, and `--json` output, and CLI output prints the full `key_id` plus actual `backend_label()`.

2. **Normative `OSPP v1` Post-`WELCOME` Capability Frames & Streaming Seed Dumps (`H-010` #1, `crates/slipfork-ospp`):**
   - `slipforkd` holds the persistent `OsppClient` WebSocket session (reconnecting lazily on demand, zero `OnceLock`/`static` globals). Every post-`WELCOME` control exchange is one UTF-8 JSON text frame (`<= 16_384` bytes / 16 KiB) tagged by `"type"`; `project` is a validated `ProjectSlug` (`1..=63`), `mode` is `1..=32` bytes (`[a-z0-9_-]`), and `key`/`db_id` are `1..=256` printable ASCII bytes without `"` or `\`. Any capability frame before `WELCOME` is a protocol violation on either side:

     | `type` tag | Client request JSON fields | Server response JSON fields & wire rules |
     |---|---|---|
     | `"env.bundle"` | `{ "type": "env.bundle", "request_id": u32, "project": str, "mode": str }` | `{ "type": "env.bundle", "request_id": u32, "vars": {k:v}, "secrets": {k:v}, "domains": {k:v} }` (`vars`/`secrets`/`domains` default `{}`; `domains` applies strictly to `cloud` mode) |
     | `"secrets.ensure"` | `{ "type": "secrets.ensure", "request_id": u32, "project": str, "mode": str, "key": str, "proposed": str }` | `{ "type": "secrets.ensure", "request_id": u32, "key": str, "value": str }` (`put_if_absent` compare-and-set returning the single authoritative stored secret) |
     | `"resources.describe"` | `{ "type": "resources.describe", "request_id": u32, "project": str, "mode": str }` | `{ "type": "resources.describe", "request_id": u32, "s3_buckets": {<id>: {endpoint, region, bucket, access_key, secret_key}}, "pg_databases": {<id>: {db_id, sha256_compressed, compressed_bytes, format: "pg_custom_zstd"}} }` |
     | `"dump.begin"` .. `"dump.end"` | `{ "type": "dump.begin", "request_id": u32, "project": str, "mode": str, "db_id": str }` | `{ "type": "dump.begin", "request_id": u32, "db_id": str, "sha256_compressed": "<64 hex>", "compressed_bytes": u64, "format": "pg_custom_zstd" }`, followed by 0+ **binary** WebSocket frames (`<= 65_536` bytes / 64 KiB each), terminated by `{ "type": "dump.end", "request_id": u32, "sha256_compressed": "<64 hex>", "compressed_bytes": u64 }` |
     | `"capability.error"` | *(any capability request)* | `{ "type": "capability.error", "request_id": u32, "capability": str, "kind": str, "message": str }` (`kind` e.g. `"not_authenticated"`, `"invalid_request"`, `"unknown_resource"`, `"unsupported_capability"`; client verifies `(request_id, capability)` match and **withholds** server free-text `message` from diagnostics so refusals never echo secrets) |

   - **`SecretProvider` & Zero-FS Boundary:** `OsppSecretProvider` implements `SecretProvider` (`Send + Sync`, `&self`) over `env.bundle` / `secrets.ensure` with **zero filesystem writes**; in `local` mode, `LayeredSecretProvider` (`slipfork-snow`) reads `FileVaultProvider` (`0600`) first then `OsppSecretProvider` and writes newly generated `!!` secrets exclusively to `FileVaultProvider` (`H-003`).
   - **`dump.begin..dump.end` Sequencing & Engine-Agnostic Restore:** Binary WebSocket frames are legal **only** between `dump.begin` and `dump.end` (`<= 64 KiB` per frame); any binary frame outside that window, any frame `> 64 KiB`, close before `dump.end`, `zstd` error, or SHA-256 / byte-count mismatch against `dump.begin`/`dump.end` fails closed and unlinks `<sha256>.part` **before** any DB mutation. `DumpStreamer` streams through a bounded `zstd` window + incremental SHA-256 into `SeedDumpStore::write_from(&self, sha256_compressed, &mut dyn Read)` (`DiskSeedDumpStore` over non-`tmpfs` `<cache_root>/dumps/`). Verified `<sha256>.pgdump` files mount `MountMode::ReadOnly` into the `base` world via `WorldSpec.mounts` **and** into the running `postgres:<v>` container via that service's `ServiceRuntime::OciContainer` `readonly_mounts` (`ADR-0009` §2), and restore via `WorldEngine::exec_in_service` **inside that container** (`pg_restore --no-owner --no-privileges --clean --if-exists` — the app stage carries no `pg_restore`, so dump/restore versions can never skew), followed by `CHECKPOINT;` in the same container and `WorldEngine::freeze_world` **before** `pre-deploy` migrations. Non-zero `pg_restore`/`CHECKPOINT`, or a container that is not `ServiceState::Running` (`EngineError::ServiceNotRunning`), fails closed via §4's rescue UX — never retried inside the world rootfs.

3. **World-Scoped `[resources]` `ResourceStrategy`, `OsppClient::resource_offer`, Port-Aware `WorldOrigin::local` & Engine-Owned In-Netns Bridge (`H-010` #2):**
   - `ResourceMode { Local, Test }` (`Serialize` only, never `Deserialize`) derives strictly from **`WorldTarget`** (`WorldTarget::TestSlot(_) => ResourceMode::Test`; `Canonical | UserFork(_) => ResourceMode::Local`; `cloud` is absent because cloud resources belong to the remote control plane's `EnvGroup`), guaranteeing M3's pre-warmed `TestSlot` pool is hermetically `Test` by construction.
   - `SlipforkConfig.resources: ResourcesSpec` parses `[resources.s3_buckets.<id>]` and `[resources.pg_databases.<id>]` tables with optional `local` and `test` keys set to `ResourceStrategy { Local, PreferRemote, Remote }` (`"local" | "prefer_remote" | "remote"`, `#[serde(deny_unknown_fields)]`, zero boolean mode flags; unknown keys, unknown modes, or empty tables fail closed at `parse_toml`, and `slipforkd` cross-checks declared IDs against `SnowFile` via `ResourcesSpec::validate_declared_ids`).
   - **Single Offer Mapper (`OsppClient::resource_offer`) & Single Resolution Owner (`ResourcePlan::resolve`):** `crates/slipfork-ospp` exposes one pure conversion method `OsppClient::resource_offer() -> Option<slipfork_dag::RemoteResourceOffer>` mapping `RemoteResourceBundle` into `slipfork-dag`'s redacted `RemoteResourceOffer` (zero resolution logic in `slipfork-ospp`), and `slipforkd` passes that `Option<&RemoteResourceOffer>` directly into `slipfork_dag::ResourcePlan::resolve(spec: &ResourcesSpec, mode: ResourceMode, dump_policy: DumpPolicy, offer: Option<&RemoteResourceOffer>) -> Result<ResourcePlan, DagError>`, which is the **sole** decision point consumed by `slipforkd` (`up`/`fork`), `OsppClient`, and M3 `TestCoordinator`:
     - **`ResourcesSpec::defaults_for(ResourceMode::Local)` (`Canonical` / `UserFork`):** `ResourceStrategy::PreferRemote` — uses OSPP-offered shared dev S3 coordinates and dev DB seed dumps when paired and offered; when unpaired, offline, or omitted, uses world-local `ResourceCoordinates` (`127.0.0.1:9000` inside the world `netns`, served by the `seaweedfs` `crun` container over its CoW state dir, `ADR-0009` §2) / cached digest-pinned dump or clean `initdb` **while emitting one mandatory `[resources]` diagnostic line per resource** (and typed `--json` field) naming the effective strategy, resolved target (`remote` vs `local`), and reason. Per-invocation `--resources local` forces `ResourceStrategy::Local` for every resource without editing `slipfork.toml`.
     - **`ResourcesSpec::defaults_for(ResourceMode::Test)` (`TestSlot`):** `ResourceStrategy::Local` (**hermetic by default**) — always uses world-local `ResourceCoordinates` and clean `initdb -> migrate -> [fixtures.*]`, never mutating shared dev S3 or pulling dev dumps unless the resource's `test = "remote"` / `"prefer_remote"` key explicitly overrides it.
     - **Mutually Exclusive `--no-dump | --refresh-dump` (`DumpPolicy`):** CLI flags `--no-dump` (`DumpPolicy::NoDump`, skips dumps and uses clean `initdb` with diagnostic) and `--refresh-dump` (`DumpPolicy::RefreshDump`, requires live OSPP metadata check) are mutually exclusive; when neither is passed (`DumpPolicy::Default`), the effective `ResourceStrategy` decides. Both `ResourceStrategy::Remote` and `DumpPolicy::RefreshDump` **fail closed** when OSPP is unpaired, unreachable, or omits the resource (and `RefreshDump` combined with `ResourceStrategy::Local` fails closed as a configuration conflict).
   - **Port-Aware `WorldOrigin::local` & `slipfork-world-init` In-Netns Loopback Bridge (`H-010` #2, `H-011` #4):** `WorldOrigin::local(&LocalHostRoute, ingress_port: u16)` renders `http://<host>` when `ingress_port == 80` and `http://<host>:<ingress_port>` otherwise (always overriding provider `domains::`, `ADR-0005` §1). **Ownership & Single Normative Bridge Variant (`H-011` #4 Variant a):** `ReflinkNetnsEngine`'s persistent per-world PID 1 (`crates/slipfork-engine/src/bin/slipfork-world-init.rs`) owns the in-netns loopback TCP bridge via `WorldSpec.local_ingress` — inside the world's netns (where in-userns `CAP_NET_BIND_SERVICE` and per-netns `net.ipv4.ip_unprivileged_port_start=0` permit unprivileged `:80` binds), `slipfork-world-init` binds `127.0.0.1:<local_ingress_port>` and splices each accepted TCP connection to a filesystem-pathname `AF_UNIX` socket `<state_root>/http-ingress.sock` (`0600`) served by `slipforkd` alongside its TCP HTTP listeners. Variant (a) is chosen over a single pre-connected TCP fd because pathname `AF_UNIX` crosses `CLONE_NEWNET` natively and supports unlimited concurrent HTTP/WebSocket connections without multiplexing or per-request FD passing.

4. **Thin-Client `slipfork` CLI, Explicit `--state-dir`/`--runtime-dir`, Direct TTY Entry & Daemon-Owned `forward` (`H-010` #1, `crates/slipfork`):**
   - **Mode-Scoped Components:** Supervised inside `slipforkd` per `ADR-0001` §1's sole `SnowFile::effective_components(mode)` contract.
   - **Explicit Path Ownership & Zero-Setup Auto-Spawn (`H-010` #1):** `slipforkd` takes explicit typed `--state-dir <path> --runtime-dir <path>` arguments (never reading or guessing `$XDG_RUNTIME_DIR` on its own) and binds its `0600` user control socket at **`<runtime_dir>/daemon.sock`**. When `<runtime_dir>/daemon.sock` is absent on a world operation, the `slipfork` CLI resolves `state_dir`/`runtime_dir` once and **auto-spawns** `slipforkd --listen 127.0.0.1:0 --state-dir <path> --runtime-dir <path>` in the background, awaiting socket readiness — so `slipfork up`, CI jobs, and `@slipfork/opencode` e2e work **zero-setup** without systemd socket activation. Every `cwd`-sensitive `DaemonControl` request (`Up`, `Down`, `Fork`, `Logs`, `HookRun`, `ExecTarget`, `Forward`) carries an explicit `cwd: PathBuf` from the CLI so `slipforkd` never calls `current_dir()`.
   - **Uniform `--world <fork>` Selector & Hook Rescue UX:** Every world-scoped command selects non-default worlds exclusively via `--world <fork>` (zero positional `[<fork>]` aliases; omitting `--world` resolves the request's `cwd` by nearest ancestor: `.worktrees/<fork>[/...]` -> `UserFork(<fork>)`, repo root -> `Canonical`). `slipforkd` streams hook output (`<component>:<phase>`, e.g. `api:pre-deploy`) live over `<runtime_dir>/daemon.sock`, waits for declared component `internal_ports` readiness before returning `[origin]`, and treats `up` as idempotent when already running. On non-zero hook exit, Slipfork prints hook ID, exact `argv`, exit code, world ID, log path, and **full un-truncated output**, **preserves the failed world** inside `slipforkd`, and prints three rescue commands (`slipfork hook run <hook_id> --world <fork>`, `slipfork logs --world <fork> <hook_id>`, `slipfork shell --world <fork>`, noting `--no-tty` and `slipfork exec` when `!isatty`). Canonical `slipfork list --json` and `up --json` schemas live in `docs/design/target-dx.md` §1.5.
   - **Direct CLI World Entry & Daemon-Owned `forward` — Zero `SCM_RIGHTS` at the CLI <-> `slipforkd` Boundary (`H-010` #1, `H-011` #1):** Because `slipforkd` and `slipfork` run as the same user, `DaemonControl::exec_target` returns `WorldExecTarget { world, origin, entry: WorldEntryCommand, env: ExecEnv, target_argv }` over `<runtime_dir>/daemon.sock` (`0600` — the **only** IPC message permitted to carry plaintext `ExecEnv` secrets); `ExecTargetRequest.service: Option<String>` selects a backing-service container and is absent for world entry. For interactive TTY commands (`shell`, `hook run` without `--no-tty`, and `db`/`redis`), `slipfork` verifies `stdin.is_terminal()` (failing closed without a TTY and naming `hook run --no-tty` / `slipfork exec`) and spawns `entry` (`nsenter --target <init_pid>` into the world's persistent `slipfork-world-init` PID 1 on `ReflinkNetnsEngine`; `incus exec` on `IncusEngine`; for `slipfork db` / `slipfork redis` the daemon returns `WorldEngine::service_entry_command`'s `crun exec` entry into the running `postgres:<v>` / `redis:<v>` container, `ADR-0009` §3, failing closed `EngineError::ServiceNotRunning`) with `env_clear()` + `ExecEnv` and **native `Stdio::inherit()`** — requiring **zero `SCM_RIGHTS` FD passing across the CLI <-> `slipforkd` TTY boundary** and **zero `pty.rs` `unsafe` code**. Non-interactive `slipfork exec` uses `exec_target` (`slipforkd` is the sole owner of `snow.yml` env resolution; `@slipfork/opencode` routes only, `ADR-0004`), `hook run --no-tty` streams via `DaemonControl::hook_run`, and `logs` streams via `DaemonControl::logs`. For **`slipfork forward [--world <fork>] [--json] [<target>...]`**, `DaemonControl::forward` makes **`slipforkd` bind host `127.0.0.1:0` listeners in-process** and bridge each accepted connection directly to `WorldEngine::dial_world_tcp` inside `slipforkd`, replying `{targets:[{id, host_addr, uri}]}` while keeping the bridge alive for the lifetime of that open control connection (Ctrl-C / disconnect tears it down cleanly; `dial_world_tcp` never crosses CLI <-> daemon IPC).

5. **Unprivileged `LISTEN_FDS` `slipforkd`, `--listen` Mode, `ingresses` Routing & Non-Template Unit Generator (`H-010` #1, `crates/slipfork-edge`):**
   - **Non-Template `slipfork daemon unit` (`UnitSpec`):** Purely renders non-template `slipforkd.socket` (fixed listener order: `ListenStream=127.0.0.1:80`, `ListenStream=[::1]:80`, `ListenStream=127.0.0.1:<forward_port>`, `NoDelay=true`, `Service=slipforkd.service`) and `slipforkd.service` (`Type=simple`, explicit `User=<developer-user>` resolved once at the CLI composition boundary via `UserIdentity` / `getpwuid_r(geteuid())`, `ExecStart=<executable> --state-dir <state_dir> --runtime-dir <runtime_dir>`, empty `CapabilityBoundingSet=`, `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ReadWritePaths=<state_dir> <runtime_dir>`, `PrivateTmp=yes`, `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX`), supporting `--only socket|service` and `--forward-port <u16>` and failing closed on empty/`%`-template `user`, empty `listen_addrs` (`EdgeError::UnitNoListener`), or port collision (`EdgeError::UnitPortCollision`).
   - **Explicit FD-Order Activation & `--listen` Rule (`adopt_systemd_listener`):** Using `#![forbid(unsafe_code)]` via `listenfd`, when `LISTEN_PID` or `LISTEN_FDS` is present in `activation.rs`, `slipforkd` verifies `LISTEN_PID == getpid()`, calls **`set_nonblocking(true)` immediately** on every inherited socket (`fd >= 3`), and assigns roles deterministically without inspecting port numbers:
     - **`LISTEN_FDS == 1`:** `fd 3` is the sole HTTP ingress (`forward_listener = None`; `share` fails closed with `EdgeError::NoForwardListener`), enabling unprivileged `systemd-socket-activate -l 127.0.0.1:0` directly.
     - **`LISTEN_FDS >= 2` (matching `UnitSpec`'s emitted order):** leading descriptors (`127.0.0.1:80`, `[::1]:80`) become `http_listeners` and the trailing descriptor (`127.0.0.1:<forward_port>`) becomes `Some(forward_listener)`.
     - **Any other count/shape or broken fd** fails closed (`EdgeError::ActivationBroken`, or `EdgeError::ActivationMismatch` on `LISTEN_PID != getpid()`) — **never** self-binding or retrying `--listen`.
     - **Unprivileged `--listen` Mode:** Only when both activation env vars are absent does `slipforkd` bind `--listen <addr>`, which binds the HTTP ingress listener **only**; a forward listener exists in `--listen` mode **only** when `--forward-port <port>` is also passed (binding `127.0.0.1:<port>`), otherwise `share` fails closed with `EdgeError::NoForwardListener`. When neither activation nor `--listen` is provided, startup fails closed (`EdgeError::NoListener`). HTTP/1.1 headers are parsed via `httparse` (`<= 16 KiB` cap, bounded read timeout), routing `.localhost` and `shared_hosts` paths through the target world's `snow.yml` `ingresses` longest-prefix table (`ADR-0005` §1).

6. **Deterministic `<= 31`-Byte Tunnel Weaver Service Labels (`crates/slipfork-world`, normative):**
   - `WeaverServiceName` enforces `weaver-proto`'s **`SERVICE_NAME_MAX = 31`** bytes and charset `^[a-z0-9]+(-[a-z0-9]+)*$`.
   - `derive_weaver_service_name(full_label)` validates/normalizes `<project>` / `<project>-<fork>` to lowercase single-dash `[a-z0-9]` runs (failing closed if empty or invalid): if `normalized.len() <= 31` **and** it neither equals `[0-9a-f]{12}` nor ends with `-[0-9a-f]{12}`, it returns `normalized` verbatim; otherwise it computes `hash12 = hex(sha256(normalized))[..12]`, takes `prefix = normalized[..min(normalized.len(), 18)].trim_end_matches('-')` (`31 - 1 - 12 = 18`), and emits `<prefix>-<hash12>` (or `<hash12>` if `prefix` is empty), keeping verbatim and hashed codomains strictly disjoint and `<= 31` bytes.

7. **Crate Boundaries, Unified Daemon Composition Root, `H-011` Engine-Internal `slipfork-world-init` & External Gates (`H-010`, `H-011`):**
