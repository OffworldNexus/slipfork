# Lessons Learned (`docs/knowledge/LESSONS.md`)

Concise, verified host, kernel, Rust, Python, and OpenCode facts. Append 1–2 lines whenever you discover a non-obvious trap.

- **Bare `python` / `python3` / `pip` are denied globally:** Always invoke Python scripts via `uv run --no-project ...` and cached CLI tools (`ruff`, `zensical`) via `uvx --offline ...`.
- **Rust 2024 formatting in OpenCode:** OpenCode's `formatter: true` runs `rustfmt <file>` without Cargo metadata; root `rustfmt.toml` (`edition = "2024"`, `style_edition = "2024"`) keeps single-file `rustfmt` 100% identical to `cargo fmt --all -- --check`.
- **`/tmp` is a 32 GiB RAM `tmpfs` (no XFS `FICLONE`!):** Never place git worktrees, CoW snapshots, PostgreSQL `PGDATA`, or Cargo scratch dirs under `/tmp` — `tmpfs` eats RAM and returns `EOPNOTSUPP` (`95`) on `ioctl(FICLONE)`. Root `/` and `/home/remy` are on an 800 GiB XFS volume (`/dev/mapper/chulak-incus`) with native `reflink=1` CoW support; keep worktrees in `.worktrees/` and CoW state under `~/.cache/slipfork` or `.slipfork/`.
- **`unshare -Urn` (`CLONE_NEWUSER | CLONE_NEWNET`) maps UID 0 -> host `$UID`:** Inside `unshare -Urnpf --mount-proc`, processes see `uid=0` (allowing `ip link set lo up` and PostgreSQL socket binds without `initdb` complaining about root if run via mapped user or unprivileged `unshare -Un` where UID stays `$UID`? Wait: PostgreSQL `initdb`/`postgres` refuses `geteuid() == 0`! Run `unshare --user --keep-caps` or map host `$UID -> $UID` via `/proc/self/uid_map` `"$UID $UID 1"`!). **Verified fact:** Writing `"$UID $UID 1"` to `/proc/self/uid_map` (after `"deny"` to `setgroups` and `"$GID $GID 1"` to `gid_map`) keeps `geteuid() == $UID` (so `postgres` and `initdb` run happily!) WHILE still granting `CAP_NET_ADMIN` inside the userns so `ioctl(SIOCSIFFLAGS)` / `ip link set lo up` brings up isolated `127.0.0.1`!
- **Parent `~/offworld-nexus/opencode.json` MCP inheritance:** Any repo under `~/offworld-nexus/` inherits `fastmail`, `linear-offworld`, `docs`, `sheets`, and `slides` MCP servers unless `.opencode/opencode.jsonc` explicitly overrides them with `"disabled": true`.
- **Single-writer path locks & explicit `git add`:** Never run two active tasks with overlapping `paths` (`tools/plan.py` enforces this mechanically), and always stage explicit file lists (`git add -- <files>`), never `git add .`.
- **`git rev-parse` topologies & hermetic VCS tests:** Pass `LC_ALL=C` + `LANGUAGE=C` so `gettext` locales never translate diagnostics; probe `--is-bare-repository` before `--show-toplevel` because bare repos have no worktree (`--show-toplevel` exits `128` `"fatal: this operation must be run in a work tree"`), and only `"fatal: not a git repository (or any "` indicates a non-repo (broken `.git` pointers, `safe.directory`, and corrupt `.git/config` also exit `128` and must surface `stderr`). Never derive canonical slugs from `--git-common-dir` basename (submodules resolve to `.git/modules/<id>` and `--separate-git-dir` resolves to the external store; even `--separate-git-dir=<dir>/.git` has `git_dir == common`, whereas linked `git worktree` checkouts have `<toplevel>/.git` as a file and `git_dir != common`). In CLI tests, set `GIT_CEILING_DIRECTORIES=<scratch>`, `env_remove` `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE`, and pass `-c protocol.file.allow=always` for local `git submodule add`.
- **Fail-closed crate invariants break other nodes' acceptance commands:** Enforcing a new fail-closed invariant in a crate (such as `ADR-0005` §3 canonical VCS `ProjectSlug` discovery) silently broke `make bench`, whose harness lives in `poc/**` outside the enforcing node's `paths`; always re-run every milestone-level acceptance command that touches the changed contract, not just the owning node's `# Acceptance`.
- **Multithreaded `setns` into an unprivileged world `netns` fails (`EPERM`/`EINVAL`, `H-011`):** `setns(CLONE_NEWNET)` requires `CAP_SYS_ADMIN` in both the caller's and target's userns and `setns(CLONE_NEWUSER)` is `EINVAL` in multithreaded processes — enter worlds via persistent PID 1 `slipfork-world-init` + pathname `AF_UNIX` sockets (`ARCHITECTURE.md` §3.3).
- **Unprivileged `:80` bind inside a world `netns`:** Both in-userns `CAP_NET_BIND_SERVICE` (`unshare --keep-caps` with identity `"$UID $UID 1"` map) and the per-netns sysctl `/proc/sys/net/ipv4/ip_unprivileged_port_start=0` permit `slipfork-world-init` to bind `127.0.0.1:80` inside a world's private network namespace with zero host privileges.
- **Git D/F refname collision (`refs/heads/<fork>` vs `refs/heads/<fork>/wip`):** Both `files` and `reftable` Git backends forbid `refs/heads/feat` and `refs/heads/feat/wip` from coexisting; keep the branch at `refs/heads/<fork>` and store synthesized dirty snapshots under `refs/slipfork/<fork>/wip`.
- **The M1 PoC measured a host-shared-`/usr` topology, not the current design (`M2.24`/`M2.25`):** `docs/research/m1-poc-benchmark.md` (`3.21x`, `118 ms`/test) ran host `postgres`/`redis` binaries and host Chromium over the host `/usr` + `/lib` under an unprivileged `netns`. `ADR-0009` replaces that with a `Dockerfile`-derived read-only `L0` rootfs plus `crun` backing-service containers, so M1 latency numbers are a historical baseline and must be labelled as such — never quoted as the current architecture or as proof that host packages suffice.
- **Static `crun` inside unprivileged `--map-user=$UID` worlds (`M2.24`):** When `geteuid() == $UID != 0`, `crun` requires `--cgroup-manager=disabled`, explicit `user` + `pid` + `mount` + `ipc` + `uts` in `config.json` (omitting `network` to share `127.0.0.1`) with identity `uidMappings`/`gidMappings` (`$UID -> $UID`), and a read-only `/etc/passwd` bind-mount adding `$UID` — omitting `user` triggers `newuidmap` (`EPERM`) / `setresuid(0)` (`EINVAL`), omitting `pid` blocks fresh `/proc` (`EPERM`), and omitting `$UID` in `/etc/passwd` makes `postgres:18` `initdb` exit `1` (`could not look up effective user ID`).
- **`buildx --output type=local` ownership & read-only `userxattr` OverlayFS + `pivot_root` (`M2.24`):** `docker buildx build --output type=local,dest=<dir>` extracts files owned by the invoking `$UID:$GID` (never `root:root`); inside `unshare --mount`, `mount -t overlay overlay -o userxattr,lowerdir=<world_mp>:<app_rootfs> <merged>` (two lowerdirs, zero `upperdir`, zero `workdir`) mounts natively read-only (`EROFS`) on XFS (`mount -o remount,ro` on an upperdir overlay fails with `fsconfig: No changes allowed in reconfigure`), and `cd <merged> && pivot_root . .old_root && umount -l /.old_root` must `chdir` into `<merged>` before `pivot_root`.
- **virtiofs cannot survive a microVM snapshot/restore (`EBADF` dead mount):** a restored VM reconnects to a *fresh* virtiofsd which has no `FUSE_INIT`/inode state, so the mount still shows in `mount` while every `open`/`ls`/`create` fails `Bad file descriptor` — `umount` before `pause`+snapshot and `mount -t virtiofs <tag> /shared` after restore (~21–50 ms); never trust mount-table presence as workspace liveness.
- **`pgrep -x` counts zombies, so poll-based teardown measurements lie:** `pkill` + `pgrep` reported "8 VMMs alive after 45 s" merely because the parent never `wait()`ed; measure with `Popen.wait()` (Cloud Hypervisor: 8 VMs die in `75 ms` on `SIGTERM`, `130 ms` on `SIGKILL`).
- **`pkill -f "<pattern>"` over SSH can kill your own remote shell** (its command line contains the pattern) and the session exits 255; use `pkill -x <comm>`, and remember `cp --reflink=always` needs source and destination on the same filesystem (`Invalid cross-device link` from overlay `/root` to XFS `/mnt`).
- **Firecracker 1.18**: the API flag is `--api-sock` (not `--api-socket`) and its HTTP API keeps connections alive, so read-until-EOF clients hang until timeout and a healthy VMM looks dead — parse `Content-Length`; snapshots also pin absolute disk **and** vsock UDS paths, so a stale `v.sock` fails `snapshot/load` with `Address in use` and per-clone disks need a bind mount at the pinned path.
