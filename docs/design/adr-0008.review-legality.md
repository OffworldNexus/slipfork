## 2. MAJOR findings

### L-M1 — `--listen` mode cannot produce a reachable origin: the port is missing from the only legal origin constructor
- `docs/design/target-dx.md:23` advertises `slipforkd --listen 127.0.0.1:7080 --forward-port 7081` for "Container / CI / no-systemd environments (zero root needed)".
- `docs/design/target-dx.md:39` then prints `[origin] http://acme.localhost`, and `:47` instructs developers to "use the printed `origin`".
- `ADR-0005:17` makes `WorldOrigin::local(&LocalHostRoute)` the **sole** constructor of `WorldOrigin::Local`, rendering `LocalHostRoute::url()`; `crates/slipfork-world/src/lib.rs:249` renders `format!("http://{}", self.host())` — **no port**. `LocalHostRoute::host()` (`:236-248`) is documented "no scheme, no port".
- Consequence: in `--listen` mode the printed origin points at `:80`, where nothing is listening, and the ADR forbids any parallel renderer. An implementer must invent a port-carrying origin (and with it a `:80`-omission rule) — the exact invention Law 1 forbids. `systemd-socket-activate -l 127.0.0.1:0` (`NODE.md:34`) makes the ephemeral case mandatory, not hypothetical.
- **Fix:** state the rule explicitly, e.g. `WorldOrigin::local(&LocalHostRoute, ingress_port: u16)` renders `http://<host>` when `ingress_port == 80` and `http://<host>:<port>` otherwise, with `slipforkd` supplying its own bound HTTP port; and state that `--listen`-mode origins are port-qualified in `list --json` / `up --json`.

### L-M2 — `tpmd` transport is unspecified while the sync-only posture excludes the only existing client
- `ADR-0008:18` specifies *behaviour* (`KeyStorePaths` probe order, `ResumeOrCreate`, `sealed` floor, signature verification) but never the transport, framing, or dependency used to talk to `tpmd`.
- `ADR-0008:15` and `ARCHITECTURE.md:5` hard-forbid tokio/async in every crate; `ADR-0008:55` lists the workspace additions as `tungstenite`, `p256`, `zstd`, `listenfd` (+ `socket2`) — **no `tpmd-client` / `tpmd-proto`**.
- `facts.md:102,115,154` record that the reference path is async IPC through `tpmd-client`, that `tpmd-ipc` adopts the listener "before tokio adoption", and that the signer/verifier traits are async. So the declared dependency set cannot implement `TpmdDeviceKeySigner` as written.
- Consequence: M2.13 must either (a) hand-roll a third-party daemon's IPC wire protocol from source (an invented external contract — the same species of defect that `H-006` closed), or (b) smuggle a tokio runtime past the sync-only invariant. Both are illegal without an explicit decision.
- **Fix (pick one, in the ADR):** (i) declare a Slipfork-owned sync `tpmd` IPC adapter over `tpmd-proto` types with the pinned protocol version and a conformance test against the live daemon; or (ii) carve a single bounded, documented exception (one dedicated worker thread owning a tokio runtime inside `TpmdDeviceKeySigner` only); or (iii) file a `direction-challenge` if neither is acceptable. Do not leave it implicit.

### L-M3 — §2 capability frames are named but never given a wire schema, while the ADR declares itself the sole normative wire spec
- `ADR-0008:15` claims the protocol is "pinned by golden byte vectors and an in-tree reference server in `crates/slipfork-ospp/tests/critical_ospp.rs`".
- §1 is byte-exact (`challenge`, `hello`, `welcome`, `reject`, `pair_hello`, `pair_approved` — `ADR-0008:21-25`), but §2 names `EnvBundle`, `SecretsEnsure`, `ResourcesDescribe`, `DumpStream`, `dump.begin`, `dump.end` (`ADR-0008:29-31`) with **no message tags, no field sets, no error kinds, and no request/response pairing**. `dump.begin` is referenced only as a range boundary ("binary frames outside `dump.begin..dump.end` fail closed").
- Consequence: M2.13/M2.14 invent the capability schema, then the "golden vectors" ratify whatever was invented — the ADR is no longer the normative spec it claims to be, and a downstream implementer (Kerfufoo) cannot implement from it.
- **Fix:** add a compact normative message table for §2 (tag, direction, fields, terminal error kinds), mirroring §1's precision; state explicitly that golden vectors are *derived from* the ADR, not the source of truth.

### L-M4 — `DumpPolicy` is per-invocation, but the dump is frozen into a content-addressed `base` snapshot; cache semantics are unstated
- `ADR-0008:31` restores the verified dump into "the `base` world", runs `CHECKPOINT;`, then `WorldEngine::freeze_world` — i.e. the dump is **baked into the `base` snapshot**.
- `ADR-0008:38` then makes `DumpPolicy` a per-invocation precedence (`Skip` > `Refresh` > `ResourceStrategy`), and `ADR-0003:16-18` defines `base` as a `per_world = false` fixture node hashed from `(id, parent_digest, run_cmd, "shared", envs, input_files)` with `DigestCache` reuse.
- Neither ADR says (a) whether the dump digest participates in the `base` fixture digest, (b) whether `Skip`/`Refresh` select distinct `base` lineages, or (c) that `Refresh` forces `CacheAction::Rebuild` on `base`.
- Consequence: `--refresh-dump` can silently hit a cached `base` (fail-open, contradicting "require live OSPP check; fail closed if offline", `ARCHITECTURE.md:170`), and `--no-dump` can silently keep the baked dump. An implementer must invent snapshot-lineage rules to honour either flag.
- **Fix:** state that the compressed dump digest is an input to the `base` fixture digest (so `Skip` and each new dump sha yield distinct `base` snapshots) and that `DumpPolicy::Refresh` emits `CacheAction::Rebuild` for `base` without consulting `DigestCache`, mirroring the `per_world` non-sharing rule in `ADR-0003:18`.

### L-M5 — The sole ingress has no defined default-ingress port, and `domains[]` carries no target
- `ADR-0005:26` proxies shared hosts "directly into the world's default ingress via `WorldEngine::dial_world_tcp(&world, port)`" and `ADR-0005:17` promises `snow.yml` `domains[].id` hostnames "remain valid local ingresses routed by `slipforkd`" — but no rule selects `port`.
- `snow.yml` gives `Domain { id }` only (`crates/slipfork-snow/src/model.rs:182-184`); ports exist only on `Ingress { match.prefix, target { component, port } }` (`:152-163`) and `components[].internal_ports`. So `<domain>.<project>.localhost` cannot be mapped to a component port from the manifest as it stands.
- `ARCHITECTURE.md:89` repeats the omission ("proxies … `*.localhost` via `LocalHostRoute`").
- Consequence: M2.8–M2.10 must invent a `snow_domain → component/port` rule (or a "first ingress wins" rule) that then silently becomes contract. This is a specification blind spot of exactly the kind Law 2 says to escalate rather than paper over.
- **Fix:** state one rule in `ADR-0005` §1 (recommended: all `*.localhost` traffic proxies to the world's single default ingress port = the `ingresses[]` entry whose `match.prefix` is `/`, falling back to the first declared component `internal_ports[0]`; `Host` is preserved and `snow_domain` is used only for vhost dispatch and `308`/`421` decisions). If instead each `domains[].id` must reach a *different* component, that is a `snow.yml` schema change — file a `direction-challenge` instead of guessing.
