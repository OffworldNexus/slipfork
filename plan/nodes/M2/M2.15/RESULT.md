## What changed

### `tools/check_support.py` (new, stdlib only, `uv run --no-project`)

- **`--check` (default, read-only, wired into `make check` as `support-check`):** reads the registry
  exclusively through `cargo run -q -p slipfork -- support --json`, so every tier requirement comes
  from the single Rust ladder (`required_evidence`). It verifies, fail-closed:
  - every tier-required pointer is present (missing/blank → violation naming the integration id);
  - **all present** file pointers (`recipe_page`, `signoff_doc`, `deploy_ref`,
    `production_suite_ref`, `test_audit`) exist inside the repository (absolute/`..` escapes
    rejected);
  - every `critical_test` resolves to `crates/<crate>/tests/critical_*.rs` and a real `fn name(`;
  - every `ci_job` (`<workflow.yml>#<job_id>`) names an existing `.github/workflows/` file and a
    real key under `jobs:`;
  - every `signoff_commit` is lowercase 40-hex, exists (`git cat-file -e <sha>^{commit}`), and
    touches its `signoff_doc` (`git diff-tree --no-commit-id --name-only -r <sha>`);
  - unknown evidence fields / unknown tiers fail closed;
  - `docs/support-matrix.md` is byte-identical to the deterministic renderer (drift names the line).
  It never writes a file. `--json` emits `{ok, integrations[], errors[]}`.
- **`--sync` (the only mutator, `make support-sync`):** for an entry whose claimed-tier evidence is
  missing/broken, demotes to the **highest strictly lower tier** whose required evidence is fully
  present (never promotes), prints `id from -> to (missing: …)`, rewrites only the affected
  `tier = "..."` lines in `support/integrations.toml`, and regenerates `docs/support-matrix.md`.
  If no lower tier is satisfied it exits non-zero without writing (fail closed, `H-009` Option B).
  Tier requirements for candidate tiers are consumed from the CLI rows; an unrepresented tier is a
  hard error rather than a Python copy of the ladder.

### `poc/run_benchmark.py` (rewritten, non-contaminating and honest)

- **`bench_child_env` allowlist:** children inherit exactly `PATH`, `LANG`, `LC_ALL`, `LC_CTYPE`
  (each omitted when absent) plus explicit `SLIPFORK_*` run variables; `HOME`/`TMPDIR` are pinned
  inside the run directory. `PYTHONPATH`, `CARGO_HOME`, `RUSTUP_HOME`, `XDG_*` can never leak.
- **Fail-closed pre-run wipe:** `prepare_run_state` removes and recreates the run directory
  (default `~/.cache/slipfork/bench`, `--run-dir` override), refuses `/tmp` and `/dev/shm`, aborts
  non-zero before timing when removal fails or the directory is non-empty, and hard-errors on any
  leftover entry.
- **Read-only default:** `--check` (default, `make bench`) re-measures, prints a metric diff, pins
  the committed report's SHA-256 to `poc/bench-baseline.json`, and exits non-zero on drift or on a
  mutated report — without writing. `--write-report` (`make bench-update`) is the only mutator.
- **0.2.0 CLI alignment:** every world operation now uses `up --no-dump`, `fork <name>`,
  `exec [--world] --cwd --`, and `drop <name>` over the auto-spawned `slipforkd`; M1's deleted
  `snap`, `fork --from`, `--workspace`, and `--snow-file` calls are gone, and the dead
  `--quick-verify` flag is deleted.
- **Measured `initdb -> seed -> pg_dump -> pg_restore`** case added; CoW fork/exec/drop,
  4-parallel-worlds-same-port, and `dag plan` warm/front rows are measured live. Dispatch order is
  derived from the explicit `--seed`.
- **One projection:** `primitive_rows`/`suite_rows` feed both `render_markdown_table` and
  `render_html_table` (`--html` prints the HTML projection); no second hand-maintained row list.
- **Report honesty:** the rendered report states the `0.2.0` read-only `L0` rootfs + `crun`
  topology and that the committed M1 figures were measured on the pre-`ADR-0009`
  **host-shared-`/usr`** topology and are not comparable.

## Honest limitations / lead actions

1. **Live re-measurement was not executed on this host.** `0.2.0` worlds need a provisioned static
   `crun`, OCI images, and a `docker buildx` project image (network); this environment has none of
   those, and the committed report is the historical M1 measurement (host-shared-`/usr`), which is
   explicitly retained and labelled. `--check` therefore fails closed here with an actionable
   prerequisite message (exit `2`) instead of inventing numbers. All hermetic/read-only/projection
   logic is unit-tested; `--check --help` (acceptance) exits `0`.
2. **`make bench` at `M2.20` needs a provisioned host:** because the committed report is a
   different topology/baseline, the first successful run will report drift and require
   `make bench-update` + review before `make bench` (read-only) can be green on that host.
3. **`ts-test` red in the shared tree** is `M2.18`'s concurrent uncommitted plugin work; not
   caused by this node (verified clean in an isolated `e5ac58f` worktree).
4. **New files for explicit staging:** `tools/check_support.py`, `tools/tests/test_check_support.py`,
   `tools/tests/test_run_benchmark.py`, `poc/bench-baseline.json`, `docs/support-matrix.md`, plus
   modified `Makefile` and `poc/run_benchmark.py`.
