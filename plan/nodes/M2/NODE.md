# Goal

Deliver Slipfork `0.2.0`:
1. **Architecture & DX Lock (`M2.1`, `M2.24`, `M2.25`):** Amend `ADR-0001`/`ADR-0005`/`ADR-0007`, author `ADR-0008` (`OSPP v1` WebSocket protocol replacing M1's REST sketch + `tpmd` ECDSA P-256 `p256:<hex>` challenge-response auth & browser-fragment pairing + remote resource coordinates + streaming `zstd`/`pg_restore` dev DB dumps restored inside the service container + mode-aware `[resources]` `ResourceStrategy` + inspectable hook/migration failure UX + service access/forwarding), author `ADR-0009` (`Dockerfile`-derived `L0` world rootfs + daemonless `crun` backing-service containers + `$UID:$GID` runtime + 6-rule World Image Contract), and update `ARCHITECTURE.md`, `docs/design/world-base-image.md` & `docs/design/target-dx.md` with zero published vaporware and every ADR/node spec swept consistent.
2. **Single-Origin `.localhost` Edge (`slipforkd`) & `<= 31`-Byte Tunnel Service Labels:** `WorldOrigin = Local { url } | Shared { url }` + deterministic `<= 31`-byte Tunnel Weaver service-label truncation (`<prefix>-<hash>`) in `crates/slipfork-world`; unprivileged `slipforkd` sole local + shared ingress (`LISTEN_FDS` socket activation with `set_nonblocking(true)` + `--listen` tested via `systemd-socket-activate -l 127.0.0.1:0`, `slipfork daemon unit`), `WorldRegistry`, `shared_hosts` map, and `*.localhost`-scoped `308`/`421` rules (`H-008`).
3. **Full `WorldEngine`, Live Hook Debugging & Service Access CLI:** Complete `WorldEngine` (`freeze_world` stopping `WorldProcess` services then `crun` `OciContainer` services before sealing `state_dir`, one `spawn_service` surface over `ServiceRuntime { WorldProcess, OciContainer }`, `exec_in_service` + `service_entry_command`, interactive TTY exec + live-streamed hook output, `dial_world_tcp`, multi-mount `WorldSpec` carrying `WorldRootfs`, redacted `ExecEnv` & `S3Coordinates` `Debug`) on live `ReflinkNetnsEngine`; failed hooks/migrations keep the world inspectable and print 1-line `slipfork hook run`, `slipfork logs`, and `slipfork shell` rescue commands; interactive lifecycle & service CLI (`up`, `down`, `shell`, `hook run`, `logs`, `db`, `redis`, `forward`, `share [--stop]`, `list`, `prune`, `secret set`, `auth login`) with `db`/`redis` entering the running `postgres:<v>`/`redis:<v>` service container.
4. **`OSPP v1` WebSocket Client, `VcsWorkspace`, `@slipfork/opencode` E2E & `H-009` Support Hygiene:** `OSPP v1` WebSocket client + `tpmd`/software P-256 signer + streaming DB seed/remote S3 `ResourceStrategy` verified against an in-tree WebSocket server conformance harness (while offline laptops stay 100% functional on `0600` `FileVaultProvider`); `VcsWorkspace` (`GitWorktreeAdapter` + `JjWorkspaceAdapter` + `git-remote-slipfork`); `H-009` Option B cleanup (`incus-engine` omitted from `support/integrations.toml` until user-reachable CLI ships), `slipfork support [--json]`, generated docs support matrix, read-only `make check` ceiling + `make support-sync`, and non-contaminating `make bench`; plus strictly isolated leaf tasks for live `IncusEngine` (gated on `H-004`) and `WeavedRegistrar` (gated on `H-006`) blocking nothing else in `M2`.
