# M1.7 RESULT — Repair `make bench` VCS root setup, regenerate live PoC report, ratify `CHANGELOG.md` (`0.1.0`)

## Summary

`make bench` was failing because `M1.6` made canonical VCS `ProjectSlug` discovery
(`ADR-0005` §3) fail closed, while `poc/run_benchmark.py` created `acme-shop` as a
plain directory outside any Git/Jujutsu repository. The benchmark harness now:

- runs a real (idempotent) `git init -q` in the sample project;
- builds one sanitized child environment (`bench_child_env`) shared by **every**
  benchmark subprocess: `GIT_CEILING_DIRECTORIES=<bench_root>`,
  `XDG_DATA_HOME=<bench_root>/xdg-data`, and ambient `GIT_DIR` /
  `GIT_WORK_TREE` / `GIT_INDEX_FILE` / `GIT_COMMON_DIR` /
  `GIT_OBJECT_DIRECTORY` / `GIT_ALTERNATE_OBJECT_DIRECTORIES` /
  `GIT_NAMESPACE` / `GIT_PREFIX` stripped;
- keeps the run hermetic: nothing is written to
  `~/.local/share/slipfork/vaults/`, and a completed run removes its bench root
  under `~/.cache/slipfork-m1-bench/` (a killed run can leave that directory
  behind; the pre-run wipe currently swallows `rmtree` errors — see
  `FOLLOWUPS.md` #3 and #9);
- renders the report date/host kernel/arch dynamically (dated `2026-11-15`) and
  measures the `PGDATA` file count instead of hardcoding `~950` files.

`CHANGELOG.md` now ratifies `0.1.0` with only shipped surfaces, and
`README.md` / `docs/index.md` cite the regenerated report's numbers.
